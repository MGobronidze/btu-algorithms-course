01 — ამოცანა 1

Same Tree

ამოცანა: მოცემულია ორი ორობითი ხის root, დაადგინეთ, სტრუქტურულად იდენტურია თუ არა ისინი — იგივე კვანძების განლაგება და იგივე მნიშვნელობები.

same_tree.py
def is_identical(r1: "Node", r2: "Node") -> bool:
    # ორივე ცარიელია — იდენტურია
    if r1 is None and r2 is None:
        return True
    # მხოლოდ ერთი ცარიელია — ვერ იქნება იდენტური
    if r1 is None or r2 is None:
        return False
    # მონაცემიც უნდა ემთხვეოდეს, და ორივე ქვეხეც რეკურსიულად
    return (r1.data == r2.data and
            is_identical(r1.left, r2.left) and
            is_identical(r1.right, r2.right))
💡

ეს არის DFS, ჩვეული ჩონჩხის მცირე ვარიაცია: ლექცია 10-ის სამივე შემოვლის ალგორითმის მსგავსად, აქაც ვამოწმებთ საბაზისო შემთხვევას და შემდეგ რეკურსიულად ვამუშავებთ ორივე ქვეხეს — უბრალოდ ერთი ხის ნაცვლად, ორ ხეს ერთდროულად ვშემოივლით, ნაბიჯ-ნაბიჯ პარალელურად.

02 — ამოცანა 2

Maximum Depth of Binary Tree

ამოცანა: გამოთვალეთ ხის სიმაღლე — ყველაზე გრძელი გზა root-იდან ფოთლამდე.

def height(root: "Node") -> int:
    if root is None:
        return -1
    left_height = height(root.left)
    right_height = height(root.right)
    return max(left_height, right_height) + 1
⚠️

ყურადღება — ორი განსხვავებული კონვენცია: ზემოთ მოცემული ვერსია იყენებს edge-height-ს — ცარიელი ხისთვის აბრუნებს -1-ს, ერთელემენტიანისთვის 0-ს (წიბოების რაოდენობა). LeetCode-ის „Maximum Depth of Binary Tree" (LeetCode 104) კი მოითხოვს node-count კონვენციას — ცარიელი ხე → 0, ერთელემენტიანი → 1 (კვანძების რაოდენობა). ორივე მართებულია, უბრალოდ ერთმანეთისგან 1-ით განსხვავდება — თუ LeetCode-ის ფორმატი გჭირდებათ, უბრალოდ შეცვალეთ საბაზისო შემთხვევა return -1-დან return 0-მდე.

03 — ამოცანა 3

Path Sum

ამოცანა: დაადგინეთ, არსებობს თუ არა root-დან ფოთლამდე გზა, რომლის ყველა კვანძის ჯამი ზუსტად უდრის მოცემულ რიცხვს.

რეკურსიული ამონახსნი

def has_path_sum(root: "Node", target_sum: int) -> bool:
    if root is None:
        return False

    remaining = target_sum - root.data

    # თუ ფოთოლს მივაღწიეთ და ჯამი ზუსტად ამოიწურა — ვიპოვეთ
    if remaining == 0 and root.left is None and root.right is None:
        return True

    left = has_path_sum(root.left, remaining) if root.left else False
    right = has_path_sum(root.right, remaining) if root.right else False
    return left or right
🔍

შესწორება ორიგინალ მასალასთან შედარებით: საწყისი კოდის რეკურსიულ ვერსიაში პარამეტრს sum ერქვა — ეს Python-ის ჩაშენებული ფუნქციის სახელს გადაფარავს (sum()). ამ კონკრეტულ ფუნქციაში ბაგას არ იწვევს (რადგან sum() შიგნით არ გამოიძახება), მაგრამ ეს საშიში პატერნია: თუ ვინმე მომავალში იმავე ფუნქციაში sum()-ის გამოძახება დასჭირდება, უცნაური და გაუგებარი შეცდომა გამოვა. საინტერესოა, რომ იმავე დეკის იტერაციული ვერსია (ქვემოთ) უკვე სწორად იყენებს targetSum-ს — გავაერთგვაროვნეთ ორივე ვერსია ამ სწორი სახელით.

იტერაციული ამონახსნი

def has_path_sum_iter(root: "Node", target_sum: int) -> bool:
    if root is None:
        return False

    stack = [root]
    sums = [root.data]

    while stack:
        node = stack.pop()
        current_sum = sums.pop()

        if node.left is None and node.right is None and current_sum == target_sum:
            return True

        if node.left:
            stack.append(node.left)
            sums.append(current_sum + node.left.data)
        if node.right:
            stack.append(node.right)
            sums.append(current_sum + node.right.data)

    return False

05 — ამოცანა 4

Invert Binary Tree

ამოცანა: გარდაქმენით ხე მის სარკისებურ ანარეკლად — გაცვალეთ თითოეული კვანძის მარცხენა და მარჯვენა ქვეხეები.

def mirror(root: "Node") -> "Node":
    if root is None:
        return None

    left = mirror(root.left)
    right = mirror(root.right)

    root.left = right
    root.right = left
    return root
🪞

ეს არის Postorder-ის ლოგიკური გამოყენება: ჯერ ვასრულებთ ორივე ქვეხის ინვერსიას (რეკურსია), მერე ვცვლით root-ის მითითებებს — ზუსტად ისე, როგორც ლექცია 10-ში Postorder-ს ვახასიათებდით, როგორც „საუკეთესოს კვანძების წაშლისთვის": ჯერ ბავშვები, მერე მშობელი.

07 — მოწინავე ტექნიკა

Morris Traversal — O(1) სივრცეში შემოვლა

დღეს არაერთხელ ვნახეთ O(h) მეხსიერების ხარჯი — თუნდაც იტერაციულ ვერსიებში, მკაფიო stack მაინც O(h)-ს მოითხოვს. არსებობს ტექნიკა, რომელიც საერთოდ გვერდს უვლის დამატებით მეხსიერებას.

🧵

იდეა: Morris Traversal დროებით იყენებს ხის საკუთარ, უკვე არსებულ None მაჩვენებლებს — კონკრეტულად, ფოთლების „თავისუფალ" right მაჩვენებლებს — რომ დროებით შექმნას „ძაფი" (thread) უკან, inorder-ის წინამორბედისკენ. ეს შესაძლებელს ხდის ხის შემოვლას stack-ის ან რეკურსიის გარეშე — O(1) დამატებით სივრცეში, O(n) დროში — შემოვლის ბოლოს კი ეს დროებითი „ძაფები" საწყის მდგომარეობას უბრუნდება, ისე რომ ხის სტრუქტურა უცვლელი რჩება.

ეს სცილდება დღევანდელი ლექციის ძირითად ფარგლებს, მაგრამ კარგი მაგალითია იმისა, რომ O(h) სულაც არაა აუცილებელი მინიმუმი — უბრალოდ საკმარისად ჭკვიანური ტრიუკებით შესაძლებელია მისი კიდევ უფრო შემცირებაც.

09 — დამატებითი ამოცანები

გაფართოებული პრაქტიკა

დღეს ნასწავლი ტექნიკების ბუნებრივი გაგრძელება.

Balanced Binary Tree მარტივი

დაადგინეთ, არის თუ არა ხე სიმაღლით-დაბალანსებული — ანუ ნებისმიერი კვანძისთვის, მისი ორი ქვეხის სიმაღლეები არაუმეტეს 1-ით განსხვავდება (LeetCode 110).

def is_balanced(root: "Node") -> bool:
    def check(node) -> int:
        if node is None:
            return 0
        left_h = check(node.left)
        if left_h == -1:
            return -1                # უკვე დაუბალანსებელია ქვემოთ
        right_h = check(node.right)
        if right_h == -1:
            return -1
        if abs(left_h - right_h) > 1:
            return -1                # -1 = "დაუბალანსებელია" სიგნალი
        return max(left_h, right_h) + 1

    return check(root) != -1

ჭკვიანური ხრიკი: -1 გამოიყენება, როგორც „უკვე დავადგინეთ დისბალანსი" სიგნალი — ამის წყალობით საკმარისია ხის ერთი გავლა (O(n)), იმის ნაცვლად, რომ თითოეულ კვანძზე ცალკე გამოვთვალოთ სიმაღლე (რაც O(n²)-ს გამოიღებდა).

Lowest Common Ancestor of a Binary Tree საშუალო

ორი კვანძისთვის იპოვეთ მათი ყველაზე „ახლო" საერთო წინაპარი ხეში (LeetCode 236).

def lowest_common_ancestor(root: "Node", p: "Node", q: "Node") -> "Node":
    if root is None or root is p or root is q:
        return root

    left = lowest_common_ancestor(root.left, p, q)
    right = lowest_common_ancestor(root.right, p, q)

    if left and right:
        return root      # p და q სხვადასხვა ქვეხეშია — root არის LCA
    return left if left else right

ეს არის Same Tree-ს ლოგიკის ბუნებრივი გაფართოება: ისევ ორი ქვეხის პარალელური რეკურსია, უბრალოდ ახლა ვეძებთ არა ტოლობას, არამედ წერტილს, სადაც ორი „ძებნის გზა" იყოფა.

Binary Tree Maximum Path Sum რთული

დღევანდელი Path Sum ამოწმებდა კონკრეტულ ჯამს root-დან ფოთლამდე. ეს ვერსია გაცილებით ზოგადია — იპოვეთ ნებისმიერი გზის მაქსიმალური ჯამი ხეში (გზა შეიძლება დაიწყოს და დასრულდეს ნებისმიერ კვანძში, root-ის ან ფოთლის გავლის გარეშეც) (LeetCode 124).

def max_path_sum(root: "Node") -> int:
    best = float('-inf')

    def gain(node) -> int:
        nonlocal best
        if node is None:
            return 0
        # უარყოფითი წვლილი უბრალოდ არ ავიღოთ (0-ით ჩავანაცვლოთ)
        left_gain = max(gain(node.left), 0)
        right_gain = max(gain(node.right), 0)

        # გზა, რომელიც ამ კვანძში "იხრება" (orost node-ს ორივე შვილს იყენებს)
        price = node.data + left_gain + right_gain
        best = max(best, price)

        # მაგრამ მშობლისთვის შეიძლება დავუბრუნოთ მხოლოდ ერთი მხარე
        return node.data + max(left_gain, right_gain)

    gain(root)
    return best

საკვანძო დაკვირვება: თითოეულ კვანძში ორი განსხვავებული რამ გვაინტერესებს — (1) საუკეთესო გზა, რომელიც ამ კვანძში იხრება (იყენებს ორივე ქვეხეს — ეს კანდიდატია გლობალური მაქსიმუმისთვის) და (2) საუკეთესო გზა, რომლის გაგრძელებაც შესაძლებელია მშობელში (მხოლოდ ერთი ქვეხე, რადგან გზა არ შეიძლება განიტოტვოს). ეს განსხვავება — რას ვაბრუნებთ vs რას ვინახავთ გლობალურად — ხშირად გვხვდება ხეების უფრო რთულ ამოცანებში.
