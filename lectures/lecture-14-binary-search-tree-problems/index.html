Validate Binary Search Tree

მოცემულია ორობითი ხის ფესვი — შევამოწმოთ, აკმაყოფილებს თუ არა ის BST-ის თვისებას. განვიხილავთ სამ მიდგომას, ერთმანეთისგან სულ სხვადასხვა სირთულით.

მაგალითები

სამივე მაგალითი აღებულია ორიგინალი მასალიდან და გადამოწმებულია სამივე ალგორითმის საშუალებით — შედეგები ემთხვევა.

მიდგომა A — გამარტივებული, მაგრამ ნელი: მარცხენა/მარჯვენა ექსტრემუმები

თითოეულ კვანძში ვამოწმებთ: მარცხენა ქვეხის მაქსიმუმი < კვანძი < მარჯვენა ქვეხის მინიმუმი. მარტივია გასაგებად, მაგრამ თითოეულ კვანძში მთელ ქვეხეს ვიმოწმებთ თავიდან — ეს ხდება ზედმეტი სამუშაო.

validate_bst_naive.py
def maxValue(node):
    if node is None:
        return float('-inf')
    return max(node.data, maxValue(node.left), maxValue(node.right))

def minValue(node):
    if node is None:
        return float('inf')
    return min(node.data, minValue(node.left), minValue(node.right))

def isBST(node):
    if node is None:
        return True
    # ქვეხის მაქსიმუმი მარცხნივ უნდა იყოს კვანძზე ნაკლები
    if node.left and maxValue(node.left) >= node.data:
        return False
    # ქვეხის მინიმუმი მარჯვნივ უნდა იყოს კვანძზე მეტი
    if node.right and minValue(node.right) <= node.data:
        return False
    return isBST(node.left) and isBST(node.right)
⚠️
ხაფანგი — ეფექტურობა ეს მიდგომა თითოეული კვანძისთვის ხელახლა გადის მთელ ქვეხეს maxValue/minValue-ით. სკელეტისებურ (degenerate, ერთი „ღეროთი") ხეზე ეს ნიშნავს, რომ საერთო სირთულე O(n²)-მდე იზრდება — 1000-კვანძიან ჯაჭვზე ეს ≈500,000 შედარებაა, მაშინ როცა B და C მიდგომები იგივეს O(n)-ში ხსნიან.

მიდგომა B — მინ/მაქს დიაპაზონის გადაცემა (რეკომენდებული, O(n))

იდეა: თითოეულ კვანძს რეკურსიის დროს „ვუთხრათ" რა დიაპაზონშია ნებადართული მისი მნიშვნელობა. ფესვისთვის დიაპაზონია (-∞, +∞). მარცხენა შვილისთვის ზედა ზღვარი ვიწროვდება მშობლის მნიშვნელობამდე, მარჯვენა შვილისთვის — ქვედა ზღვარი მკაცრდება.

validate_bst_range.py
def isBstUtil(node, min_val, max_val):
    if node is None:
        return True
    # თუ მიმდინარე მნიშვნელობა დასაშვებ დიაპაზონს გარეთაა
    if node.data < min_val or node.data > max_val:
        return False
    # რეკურსიულად ვამოწმებთ მარცხენა და მარჯვენა ქვეხეს განახლებული დიაპაზონით
    return (isBstUtil(node.left, min_val, node.data - 1) and
            isBstUtil(node.right, node.data + 1, max_val))

def isBST(root):
    return isBstUtil(root, float('-inf'), float('inf'))

ნაბიჯ-ნაბიჯ, ხის 10 → (5, 20 → (9, 25)) მაგალითზე — ეს ხე არ არის ვალიდური BST, რადგან 9 < 10, მაგრამ 20-ის (და მაშასადამე 10-ის) მარჯვენა ქვეხეშია:

1

isBstUtil(10, -∞, +∞) — ფესვისთვის ნებისმიერი მნიშვნელობაა დასაშვები.

2

მარცხენა ქვეხე: isBstUtil(5, -∞, 9) — ზედა ზღვარი გახდა 10-1=9. 5 ჯდება დიაპაზონში → ორივე შვილი None → True.

3

მარჯვენა ქვეხე: isBstUtil(20, 11, +∞) — ქვედა ზღვარი გახდა 10+1=11. 20 ჯდება.

4

20-ის მარცხენა შვილი: isBstUtil(9, 11, 19) — 9 < 11, დიაპაზონს გარეთაა → False.

5

False ვრცელდება მთელ საკლების ჯაჭვში ზემოთ — საბოლოო შედეგი False.

მიდგომა C — Inorder ტრავერსალი + წინა მნიშვნელობა

ეყრდნობა ლექცია 11-ის ცოდნას: BST-ის inorder ტრავერსალი (მარცხენა → ფესვი → მარჯვენა) ყოველთვის ზრდადი მიმდევრობაა. საკმარისია გავიაროთ inorder-ით და შევამოწმოთ, რომ ყოველი შემდეგი მნიშვნელობა წინაზე მკაცრად მეტია — მასივის შენახვა საერთოდაც არაა საჭირო.

validate_bst_inorder.py
def isValidBst(node, prev):
    if node is None:
        return True
    # მარცხენა ქვეხე
    if not isValidBst(node.left, prev):
        return False
    # მიმდინარე მნიშვნელობა შევადაროთ წინა (inorder-ით) მნიშვნელობას
    if prev[0] is not None and prev[0] >= node.data:
        return False
    prev[0] = node.data
    # მარჯვენა ქვეხე
    return isValidBst(node.right, prev)

def isBST(root):
    prev = [None]  # სია გამოიყენება, რადგან Python-ს არ აქვს pass-by-reference
    return isValidBst(root, prev)
💡
Clean Code შენიშვნა prev = [None] — ერთელემენტიანი სია — არის გავრცელებული Python-ული ხრიკი "mutable closure"-ის იმიტაციისთვის, რადგან int/None უცვლელია (immutable) და რეკურსიულ გამოძახებებში პირდაპირ ვერ შეიცვლება. უფრო თანამედროვე ალტერნატივაა კლასის ატრიბუტი ან nonlocal საკეტური ცვლადი შიდა ფუნქციაში.
მიდგომადროის სირთულედამხმარე მეხსიერებაკომენტარი
A — მარცხენა/მარჯვენა ექსტრემუმებიO(n²)O(h)მარტივი გასაგებად, არაეფექტური
B — მინ/მაქს დიაპაზონიO(n)O(h)რეკომენდებული — თითო კვანძი ერთხელ
C — Inorder + წინა მნიშვნელობაO(n)O(h)ეყრდნობა ლექცია 11-ის ტრავერსალებს

სადაც n — კვანძების რაოდენობა, h — ხის სიმაღლე (რეკურსიის სტეკი).

Search in a Binary Search Tree

ვეძებთ კონკრეტულ მნიშვნელობას BST-ში. BST-ის თვისების წყალობით, ეს არსებითად იგივე იდეაა, რაც ორმაგი ძებნა (Binary Search) დალაგებულ მასივზე (ლექცია 2–3) — უბრალოდ მასივის შუა ელემენტის მაგივრად ვირჩევთ ხის კვანძს.

🔗
კავშირი ლექცია 2-3-თან გაიხსენეთ Binary Search მასივზე: შუა ელემენტთან შედარება, შემდეგ ძებნის არეს განახევრება. BST-ში „მასივის შუა" შეცვლილია „მიმდინარე კვანძით", ხოლო „მარცხენა/მარჯვენა ნახევარი" — შესაბამისი ქვეხით. სწორედ ამიტომ ორივეს საშუალო სირთულეა O(log n).
search_bst.py
def search(root, key):
    # საბაზისო შემთხვევა: ფესვი ცარიელია, ან სწორედ ეს არის საძებნი კვანძი
    if root is None or root.key == key:
        return root
    # საძებნი მნიშვნელობა ფესვზე მეტია — გავაგრძელოთ მარჯვნივ
    if root.key < key:
        return search(root.right, key)
    # საძებნი მნიშვნელობა ფესვზე ნაკლებია — გავაგრძელოთ მარცხნივ
    return search(root.left, key)
🔍
შესწორება — ატრიბუტების შეუსაბამობა ორიგინალ მასალაში Validate BST-ის სამივე ფუნქცია იყენებს node.data-ს, ხოლო Search და (ქვემოთ) Insert — node.key-ს. ეს არ არის უბრალო სტილისტური სხვაობა: თუ ამ ფუნქციებს ერთსა და იმავე Node კლასზე პირდაპირ გამოვიყენებთ, მივიღებთ AttributeError-ს (გადამოწმებულია ქვემოთ). დღევანდელ სავარჯიშოებში ერთიანად ვიყენებთ .val-ს — LeetCode-ის კონვენციის მიხედვით — რათა ოთხივე ალგორითმი ერთ ხეზე იმუშაოს პრობლემების გარეშე.

Insert into a Binary Search Tree

ახალი გასაღები ყოველთვის ემატება ფოთლის პოზიციაზე — ისე, რომ BST-ის თვისება არ დაირღვეს. ვეშვებით ფესვიდან, თითოეულ კვანძში ვირჩევთ მიმართულებას შედარებით, სანამ ცარიელ ადგილს არ მივაღწევთ.

insert_bst_iterative.py
def insert(root, key):
    temp = Node(key)
    # თუ ხე ცარიელია, ახალი კვანძი ხდება ფესვი
    if root is None:
        return temp

    # ვეძებთ კვანძს, რომელსაც temp შვილად დაერთვება
    parent = None
    curr = root
    while curr is not None:
        parent = curr
        if curr.key > key:
            curr = curr.left
        elif curr.key < key:
            curr = curr.right
        else:
            return root  # გასაღები უკვე არსებობს — დუბლიკატებს არ ვამატებთ

    # ვამაგრებთ ახალ კვანძს სწორ მხარეს
    if parent.key > key:
        parent.left = temp
    else:
        parent.right = temp
    return root
🎯
დიზაინის არჩევანი — რეკურსია vs იტერაცია ყურადღება მიაქციეთ: search() დაწერილია რეკურსიულად, ხოლო insert() — იტერაციულად. ორივე ვალიდურია (იტერაციულს O(1) დამატებითი მეხსიერება სჭირდება O(h)-ის ნაცვლად), მაგრამ ეს აჩვენებს — BST-ის ოპერაციები ბუნებრივად შეიძლება დაიწეროს ორივე სტილში; საბოლოო არჩევანი დამოკიდებულია იმაზე, მნიშვნელოვანია თუ არა სტეკის სივრცის დაზოგვა.

ვალიდაცია, რომელსაც ხშირად ავიწყდებათ

Convert Sorted Array to Binary Search Tree

გვაქვს დალაგებული მასივი — უნდა ავაგოთ დაბალანსებული BST. იდეა „გათიშე და იბატონეა" (ისევე, როგორც Merge Sort-სა და Quick Sort-ში, ლექცია 4–5): ვირჩევთ შუა ელემენტს ფესვად, შემდეგ იგივეს ვიმეორებთ რეკურსიულად ორივე ნახევარზე.

🔗
კავშირი ლექცია 4–5-თან ეს ალგორითმი Merge Sort-ის „სარკისებური" ვერსიაა: Merge Sort მასივს ყოფს, ალაგებს ნაწილებს და მერე აერთიანებს; აქ კი უკვე დალაგებულ მასივს ვყოფთ და თითო ნაწილს პირდაპირ ვაქცევთ ხის კვანძად — შერწყმის ნაბიჯი საერთოდ არ გვჭირდება, რადგან მასივი უკვე დალაგებულია.
sorted_array_to_bst.py
def sortedArrayToBSTRecur(arr, start, end):
    if start > end:
        return None
    # შუა ელემენტი ხდება მიმდინარე ქვეხის ფესვი
    mid = start + (end - start) // 2
    root = Node(arr[mid])
    root.left = sortedArrayToBSTRecur(arr, start, mid - 1)
    root.right = sortedArrayToBSTRecur(arr, mid + 1, end)
    return root

def sortedArrayToBST(arr):
    return sortedArrayToBSTRecur(arr, 0, len(arr) - 1)

სავარჯიშოები

გამოცადეთ საკუთარი თავი

პირველი ოთხი — დღევანდელი ლექციის ძირითადი ამოცანებია. შემდეგი ჯგუფი აფართოებს იმავე იდეებს ახალი კუთხით — მოერიდეთ AVL-სა და Counting/Radix Sort-ის თემებს, ეს მომდევნო ლექციებზეა (15-16).

ძირითადი (ლექციის ამოცანები)

+Validate Binary Search TreeMedium

დაწერეთ სამივე მიდგომა (A, B, C) და გადაამოწმეთ სამივეზე ერთდაიგივე ტესტ-შემთხვევები. შეადარეთ მათი შესრულების დრო 10,000-კვანძიან დეგენერირებულ (ჯაჭვისებურ) ხეზე — თვალნათლივ დაინახავთ O(n²) vs O(n) სხვაობას.

+Search / Insert into BSTEasy

გადაწერეთ search() იტერაციულად და insert() — რეკურსიულად. დარწმუნდით, რომ ორივე ვერსია ერთსა და იმავე შედეგს იძლევა ორიგინალთან შედარებით.

+Convert Sorted Array to BSTMedium

შეასწორეთ დღეს ნაპოვნი ხარვეზი: დაწერეთ sortedArrayToBST-ის ვერსია, რომელიც წინასწარ ამოწმებს დუბლიკატებს და ან გამორიცხავს მათ, ან აგდებს ValueError-ს გასაგები შეტყობინებით.

გაფართოებული — LeetCode სტილი

+Minimum Absolute Difference in BSTEasy

იპოვეთ მინიმალური სხვაობა ნებისმიერ ორ კვანძს შორის BST-ში. მინიშნება: გამოიყენეთ inorder ტრავერსალი (მიდგომა C) — ზრდადი მიმდევრობის მეზობელ ელემენტებს შორის სხვაობა ყოველთვის საკმარისია შესამოწმებლად.

+Two Sum IV — Input is a BSTEasy

მოცემულია BST და რიცხვი k — არსებობს თუ არა ორი კვანძი, რომელთა ჯამი k-ს უდრის? მინიშნება: გადაიყვანეთ ხე მასივად inorder ტრავერსალით (ისევ მიდგომა C), შემდეგ გამოიყენეთ ორი მაჩვენებელი (two-pointer) დალაგებულ მასივზე.

+Kth Smallest Element in a BSTMedium

იპოვეთ k-ურად უმცირესი მნიშვნელობა BST-ში. მინიშნება: inorder ტრავერსალი აწარმოებს ზრდად მიმდევრობას — საკმარისია დაითვალოთ ვიზიტები და შეჩერდეთ k-ურზე, მასივის სრულად აგების გარეშე.

+Lowest Common Ancestor of a BSTMedium

იპოვეთ ორი კვანძის უახლოესი საერთო წინაპარი BST-ში. მინიშნება: გამოიყენეთ BST-ის თვისება პირდაპირ — არ გჭირდებათ მთელი ხის მოვლა, საკმარისია შედარება ფესვთან, ისევე როგორც search()-ში.

+Delete Node in a BSTHard

წაშალეთ კვანძი BST-დან ისე, რომ BST-ის თვისება შენარჩუნდეს. მინიშნება: სამი შემთხვევაა — ფოთოლი (უბრალოდ წავშალოთ), ერთი შვილი (შევცვალოთ შვილით), ორი შვილი (ვიპოვოთ მემკვიდრე მარჯვენა ქვეხის უმცირეს მნიშვნელობაში — inorder successor).

+Recover Binary Search TreeHard

ორ კვანძს BST-ში შემთხვევით გაუცვალეს ადგილი — გამოასწორეთ ხე მათი მნიშვნელობების დაბრუნებით, სტრუქტურის შეცვლის გარეშე. მინიშნება: ეს არის „მიდგომა C"-ის (inorder + prev) პირდაპირი გაფართოება — მოძებნეთ ორი ადგილი, სადაც prev >= curr.
