01 — ფორმალიზაცია

Big-O-ს მათემატიკური განმარტება

წინა ლექციაზე O-დიდი ინტუიციურად განვსაზღვრეთ — „ვინარჩუნებთ ყველაზე სწრაფად მზარდ წევრს, ვუგულებელყოფთ მუდმივებს". დროა ამას ზუსტი მათემატიკური ფორმა მივცეთ.

∑

განმარტება: ფუნქცია f(n) არის O(g(n)), თუ არსებობს დადებითი მუდმივები c > 0 და n₀ ≥ 0, ისეთები, რომ ყოველი n ≥ n₀-სთვის:

f(n) ≤ c · g(n)

სიტყვებით: g(n) არის f(n)-ის ზედა საზღვარი (upper bound) — საკმარისად დიდი n-ისთვის, f(n) არასდროს „გადააჭარბებს" g(n)-ს (მუდმივ ჯერადობამდე). სწორედ ამიტომ შეგვიძლია ვთქვათ, რომ 3n² + 5n + 2 არის O(n²) — შეგვიძლია ავირჩიოთ, მაგალითად, c = 4 და n₀ = 6, და უტოლობა ყოველთვის შესრულდება (n=6-ზე: 140 ≤ 144, და სხვაობა მხოლოდ იზრდება n-ის ზრდასთან ერთად).

02 — ლოგარითმული სირთულე

ორობითი ძებნა (Binary Search)

ორობითი ძებნა — ალგორითმი დალაგებულ სტრუქტურაში ელემენტის მოსაძებნად, რომელიც ყოველ ნაბიჯზე საძიებელ არეალს განახევრებს, სანამ არ იპოვის ელემენტს ან არეალი არ დაცარიელდება.

📋

გამოყენების ორი წინაპირობა:

1. სტრუქტურა უნდა იყოს დალაგებული — თორემ „მარჯვნივ თუ მარცხნივ წასვლის" გადაწყვეტილება აზრს კარგავს.
2. ნებისმიერ ელემენტთან წვდომა უნდა ხდებოდეს მუდმივ დროში (O(1)) — მასივისთვის ეს მართალია, მაგრამ, მაგალითად, ბმული სიისთვის (Linked List) — არა, ამიტომ ორობითი ძებნა ბმულ სიაზე პირდაპირ ასე აღარ მუშაობს.

ალგორითმის ნაბიჯები:

  1. გამოვთვალოთ შუა ინდექსი mid — არეალს ვყოფთ ორ ნაწილად.
  2. შევადაროთ შუა ელემენტი საძიებელს. თუ ემთხვევა — ვიპოვეთ, ვასრულებთ.
  3. თუ საძიებელი შუა ელემენტზე მეტია — ვირჩევთ მარჯვენა ნახევარს; თუ ნაკლები — მარცხენას.
  4. ვიმეორებთ, სანამ არ ვიპოვნით ელემენტს, ან არეალის სიგრძე ნულს არ გაუტოლდება.
03 — სცადეთ თავად

ნაბიჯ-ნაბიჯ ვიზუალიზაცია

შეიყვანეთ დალაგებული მასივი და საძიებელი რიცხვი, შემდეგ დააჭირეთ „შემდეგი ნაბიჯი" — თვალყური ადევნეთ, როგორ იკლებს საძიებელი არეალი ყოველ იტერაციაზე.

იტერაციული იმპლემენტაცია
def binary_search(arr: list, target) -> int:
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = low + (high - low) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1
რეკურსიული იმპლემენტაცია
def binary_search_rec(arr: list, low: int,
                       high: int, target) -> int:
    if low > high:
        return -1
    mid = low + (high - low) // 2
    if arr[mid] == target:
        return mid
    elif arr[mid] < target:
        return binary_search_rec(arr, mid + 1, high, target)
    else:
        return binary_search_rec(arr, low, mid - 1, target)
✅

კარგი პრაქტიკა, რომელიც უკვე სწორადაა დაცული: ორივე ვერსია იყენებს mid = low + (high - low) // 2-ს — და არა თითქოს „უფრო მარტივ" (low + high) // 2-ს. სხვა ენებში (მაგ. Java, C++), სადაც მთელი რიცხვების ზომა შეზღუდულია, low + high-მა შეიძლება overflow გამოიწვიოს დიდ მასივებზე — Python-ში ეს კონკრეტული პრობლემა არ დგას (მთელი რიცხვები თვითნებურად დიდი შეიძლება იყოს), მაგრამ ეს პატერნი ინდუსტრიის სტანდარტული, „თავდაცვითი" ჩვევაა, რომელიც ღირს ისწავლოთ ერთხელ და ყოველთვის გამოიყენოთ.

სირთულის ანალიზი: ყოველ ნაბიჯზე საძიებელი არეალი ნახევრდება: n → n/2 → n/4 → … → 1. კითხვა: რამდენჯერ შეგვიძლია n-ის გაყოფა 2-ზე, სანამ 1-ს არ მივაღწევთ? სწორედ ეს არის ლოგარითმის განმარტება: log₂(n)-ჯერ.

იმპლემენტაციადროითი სირთულემეხსიერების სირთულე
იტერაციულიO(log n)O(1)
რეკურსიულიO(log n)O(log n) — call stack

ორივეს ერთნაირი დროითი სირთულე აქვს, მაგრამ რეკურსიული ვერსია დამატებით O(log n) მეხსიერებას ხარჯავს call stack-ზე — იგივე პრინციპი, რასაც ლექცია 1-ში ვნახეთ.

04 — გამეორება მაგალითებით

სირთულის კლასები — გამეორება

კლასიწარმოშობა
O(log n)არეალის განახევრება ყოველ ნაბიჯზე — ორობითი ძებნა
O(n)ერთი, არაჩადგმული იტერაციული ციკლი — ძებნა დაულაგებელ სიაში
O(n²), O(nᶜ)c-ჯერ ჩადგმული ციკლები — მაგ. ორი სიის თანაკვეთის ნაივური ძებნა
O(2ⁿ)რეკურსიული ფუნქცია, სადაც ერთზე მეტი რეკურსიული გამოძახება გვაქვს — ჰანოის კოშკები, ფიბონაჩის ნაივური რეკურსია

პოლინომიური სირთულის (ჩადგმული ციკლების) და წრფივი სირთულის მაგალითები დეტალურად უკვე განვიხილეთ მე-2 ლექციაზე (isSubset, intersect) — აქ ვამატებთ იმ შემთხვევას, რომელიც ჯერ არ გვინახავს: ექსპონენციალურს, და ვხედავთ, საიდან ჩნდება ის ზუსტად.

05 — ყველა ქვესიმრავლის სიმრავლე

Power Set

n-ელემენტიანი სიმრავლის ყველა შესაძლო ქვესიმრავლეთა სიმრავლეს — Power Set ეწოდება. მაგალითად, {a, b, c}-ის power set შედგება 8 ქვესიმრავლისგან: ცარიელი სიმრავლიდან თავად {a,b,c}-მდე.

🔑

რატომ 2ⁿ? თითოეული ელემენტისთვის ზუსტად ორი შესაძლებლობა გვაქვს — ან შედის ქვესიმრავლეში, ან არა. n დამოუკიდებელი ორარჩევანიანი გადაწყვეტილება → 2ⁿ კომბინაცია.

მიდგომა 1 — ბიტური ნიღბები (bitmask)

თითოეული ქვესიმრავლე შეესაბამება n-ბიტიან ორობით რიცხვს: 1 ნიშნავს „ეს ელემენტი შედის", 0 — „არ შედის". {a,b,c}-სთვის: 011₂ → {a, b}, 101₂ → {a, c} და ა.შ. საკმარისია ჩავთვალოთ 0-დან 2ⁿ − 1-მდე ყველა რიცხვი.

power_set_bitmask.py
def power_set(items: list) -> list[list]:
    n = len(items)
    result = []
    for mask in range(1 << n):          # 0-დან 2ⁿ − 1-მდე
        subset = [items[j] for j in range(n) if mask & (1 << j)]
        result.append(subset)
    return result
🔍

სამი შესწორება ორიგინალი მასალიდან:

1. საწყისი კოდი იყენებდა ცვლადის სახელს set — ეს გადაფარავს Python-ის ჩაშენებულ set ტიპს იმავე scope-ში; შემდეგ იმავე ფუნქციაში set()-ის გამოძახება უკვე ვეღარ იმუშავებდა. ჩაშენებული ტიპების/ფუნქციების სახელების გადაფარვა კლასიკური, ადვილად თავიდან ასაცილებელი ბაგია.

2. (int) (math.pow(2, n)) — C/Java-სტილის „cast" სინტაქსია; Python-ში ის ტექნიკურად მუშაობს (რადგან (int) უბრალოდ int ტიპის მიმართვაა ფრჩხილებში), მაგრამ არაიდიომატურია და შემცდომია დამწყებთათვის. ბიტურ ალგორითმში ბუნებრივი და ზუსტი ალტერნატივაა 1 << n — რჩება მთელ რიცხვებში, float-ის გავლის გარეშე.

3. გამოტოვებულია ცალკე ფუნქცია — ორიგინალი მხოლოდ print-ავდა შედეგს; ეს ვერსია სიმრავლეს აბრუნებს, რაც ტესტირებადს ხდის (იგივე პრინციპი, რასაც ჰანოის მაგალითში ვიყენებდით).

მიდგომა 2 — რეკურსია

თუ უკვე გვაქვს ყველა ქვესიმრავლე პირველი n−1 ელემენტისთვის, n-ური ელემენტის power set-ს ორი ნაწილისგან ავაწყობთ: ძველი ქვესიმრავლეები (ახალი ელემენტის გარეშე) + იგივე ქვესიმრავლეები (ახალი ელემენტის დამატებით).

power_set_recursive.py
def gen_subsets(items: list) -> list[list]:
    if len(items) == 0:
        return [[]]                         # ერთადერთი ქვესიმრავლე — ცარიელი
    smaller = gen_subsets(items[:-1])        # ყველა ქვესიმრავლე ბოლო ელემენტის გარეშე
    last = items[-1:]
    with_last = [s + last for s in smaller]  # იგივეები + ბოლო ელემენტი
    return smaller + with_last

(ორიგინალში იყო გამოუყენებელი ცვლადი res = [], რომელიც არსად გამოიყენებოდა — წაშლილია.)

მიდგომადროითი სირთულე
ბიტური ნიღბებიO(n · 2ⁿ)
რეკურსიაO(n · 2ⁿ)

ორივეს ერთი და იგივე ასიმპტოტური სირთულე აქვს: 2ⁿ ქვესიმრავლე გენერირდება, თითოეულს კი (საშუალოდ) O(n) დრო სჭირდება კოპირებისთვის — ჯამში O(n · 2ⁿ). ეს არ არის ალგორითმის „ხარვეზი" — თავად პასუხი ექსპონენციალურად დიდია, ამიტომ ნებისმიერი ალგორითმი, რომელიც მას მთლიანად აგენერირებს, მინიმუმ ამდენ დროს მოითხოვს.

06 — რეკურენტული დამოკიდებულების ამოხსნა

ჰანოის კოშკები — რატომ ზუსტად 2ⁿ − 1

ლექცია 1-ში ვნახეთ, რომ ჰანოის ამოცანას 2ⁿ − 1 გადატანა სჭირდება — ახლა ამას მათემატიკურად დავამტკიცოთ. თუ tₙ აღვნიშნოთ, როგორც n-ზომის კოშკის გადასატანად საჭირო დრო:

tn = 2tn−1 + 1
   = 2(2tn−2 + 1) + 1 = 4tn−2 + 2 + 1
   = 4(2tn−3 + 1) + 2 + 1 = 8tn−3 + 4 + 2 + 1
   = … = 2ᵏtn−k + 2ᵏ⁻¹ + ⋯ + 4 + 2 + 1
   = … = 2ⁿ⁻¹ + 2ⁿ⁻² + ⋯ + 4 + 2 + 1 = 2ⁿ − 1

ბოლო ტოლობა გეომეტრიული პროგრესიის ჯამის ფორმულიდან გამომდინარეობს: 1 + 2 + 4 + ⋯ + 2ⁿ⁻¹ = 2ⁿ − 1. შედეგი — ზუსტად O(2ⁿ), ისე, როგორც ინტუიციურადაც მოსალოდნელი იყო: ყოველი დონე რეკურსიისა ორმაგდება.

07 — უფრო ზუსტი შეფასება

ფიბონაჩი და ოქროს კვეთა

წინა ლექციაზე ფიბონაჩის ნაივურ რეკურსიას O(2ⁿ) მივანიჭეთ — ეს სწორია, როგორც ზედა საზღვარი (რადგან ყოველი გამოძახება ≤2 შვილ-გამოძახებას წარმოშობს), მაგრამ არ არის ყველაზე მჭიდრო შეფასება.

fib_recur.py
def fib_recur(n: int) -> int:
    if n == 0:
        return 0
    elif n == 1:
        return 1
    else:
        return fib_recur(n - 1) + fib_recur(n - 2)
φ

უფრო მჭიდრო შეფასება: გამოძახებების ხის ზრდის ზუსტი ტემპი განისაზღვრება ოქროს კვეთით (φ = (1+√5)/2 ≈ 1.618) — ფიბონაჩის მიმდევრობის საკუთარი „ბუნებრივი მუდმივით":

T(n) = O(φⁿ) ≈ O(1.618ⁿ)

ეს მკაცრად ნაკლებია, ვიდრე O(2ⁿ) — მაგრამ ორივე მაინც ექსპონენციალურია, ანუ პრაქტიკულად ერთნაირად „უსარგებლო" კლასს განეკუთვნება დიდი n-ისთვის. სწორედ ამიტომ საკმარისი და მისაღები იყო O(2ⁿ)-ის დასახელება ლექცია 2-ში — ზედა საზღვარი მჭიდრო არ იყო, მაგრამ ასიმპტოტურ კლასს სწორად ასახავდა.

საბედნიეროდ, ორივე ეს რიცხვი მთლიანად უსარგებლოა, თუ უბრალოდ იტერაციულად ვთვლით — მხოლოდ ბოლო ორი მნიშვნელობის დამახსოვრებით:

fib_iter.py
def fib_iter(n: int) -> int:
    if n == 0:
        return 0
    elif n == 1:
        return 1
    fib_i, fib_ii = 0, 1
    for _ in range(n - 1):
        fib_i, fib_ii = fib_ii, fib_i + fib_ii
    return fib_ii

იტერაციული ვერსია მხოლოდ ორ ცვლადს ინახავს — არც მთელი მემოიზაციის ცხრილი სჭირდება, არც call stack. ეს საუკეთესო შესაძლო ვარიანტია ამ კონკრეტული ამოცანისთვის — O(n) დროში და O(1) მეხსიერებაში.

08 — ოპერაციების სირთულე

მთელი რიცხვის სტრიქონში კონვერტაცია

ბოლო მაგალითი გვიჩვენებს, რომ პროდუქციაში მისაღები კოდის დაწერას ბევრი წვრილმანის გათვალისწინება სჭირდება — ერთი გამოტოვებული შემთხვევა საკმარისია რეალურ ბაგემდე.

int_to_str_original.py
def intToStr(i):
    digits = '0123456789'
    if i == 0:
        return '0'
    result = ''
    while i > 0:
        result = digits[i % 10] + result
        i = i // 10
    return result
🐞

რეალური ბაგი — უარყოფითი რიცხვები საერთოდ არ მუშავდება: intToStr(-42) აბრუნებს ცარიელ სტრიქონს ''-ს, სწორი "-42"-ის ნაცვლად! მიზეზი: ციკლის პირობა while i > 0 არასდროს სრულდება უარყოფით i-ზე — ციკლი საერთოდ არ იწყება. ეს ზუსტად იმ ტიპის ბაგია, რომელიც ტესტირებისას (მხოლოდ დადებითი მაგალითებით) შეიძლება შეუმჩნეველი დარჩეს.

🔍

წარმადობის დამატებითი შენიშვნა: result = digits[i%10] + result ყოველ იტერაციაზე ქმნის ახალ სტრიქონს (Python-ში სტრიქონები უცვლელია — immutable), რაც ამ კონკრეტულ კონტექსტში უმნიშვნელოა (რიცხვს რამდენიმე ათეული ციფრი აქვს მაქსიმუმ), მაგრამ ზოგადი პრინციპისთვის ღირს ცოდნა: ციკლში სტრიქონების განმეორებითი შეერთება დიდ მონაცემზე O(k²)-მდე შეიძლება გაიზარდოს (k — საბოლოო სტრიქონის სიგრძე). ინდუსტრიული სტანდარტია სიმბოლოების სიაში დაგროვება და ბოლოს ერთი ''.join(...)-ის გამოძახება — O(k)-ში.

int_to_str_fixed.py
def int_to_str(i: int) -> str:
    digits = '0123456789'
    if i == 0:
        return '0'
    is_negative = i < 0
    i = abs(i)
    chars = []
    while i > 0:
        chars.append(digits[i % 10])
        i //= 10
    if is_negative:
        chars.append('-')
    return ''.join(reversed(chars))

სირთულე: O(log₁₀ i) — ციფრების რაოდენობა რიცხვში იზრდება ლოგარითმულად, თავად რიცხვის სიდიდესთან შედარებით.

10 — პრაქტიკა

ინტერაქტიული სავარჯიშოები

საბაზისო სავარჯიშოები

1. დაწერეთ ორობითი ძებნა მარცხნიდან მარჯვნივ დალაგებულ სიაზე — შეაფასეთ სირთულე 
def binary_search(arr: list, target) -> int:
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = low + (high - low) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

სირთულე: O(log n). საძიებელი არეალი ყოველ ნაბიჯზე ნახევრდება.

2. დაწერეთ ფუნქცია, რომელიც დააბრუნებს სიმრავლის ყველა ქვესიმრავლეს — შეაფასეთ სირთულე 
def power_set(items: list) -> list[list]:
    n = len(items)
    return [[items[j] for j in range(n) if mask & (1 << j)]
            for mask in range(1 << n)]

სირთულე: O(n · 2ⁿ). 2ⁿ ქვესიმრავლე, თითოეულის აგებას საშუალოდ O(n) სჭირდება.

Search in Rotated Sorted Array საშუალო

მასივი დალაგებული იყო, შემდეგ „დაბრუნდა" უცნობ წერტილში (LeetCode 33). მთლიანად დალაგებული აღარაა, მაგრამ ორობითი ძებნა მაინც გამოსადეგია — ყოველ ნაბიჯზე ერთი ნახევარი მაინც დალაგებულია.

def search(nums: list, target: int) -> int:
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[lo] <= nums[mid]:            # მარცხენა ნახევარი დალაგებულია
            if nums[lo] <= target < nums[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:                                 # მარჯვენა ნახევარი დალაგებულია
            if nums[mid] < target <= nums[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    return -1

სირთულე რჩება O(log n) — ყოველ ნაბიჯზე მაინც ვაგდებთ ნახევარს, თუნდაც ცოტა უფრო ფრთხილი ლოგიკით.

Koko Eating Bananas — Binary Search on Answer რთული

კოკოს h საათი აქვს ბანანის piles გროვების შესაჭმელად, საათში მუდმივი სისწრაფით k. იპოვეთ მინიმალური k, რომლითაც ყველაფერს მოასწრებს (LeetCode 875).

def min_eating_speed(piles: list, h: int) -> int:
    def hours_needed(speed: int) -> int:
        return sum((p + speed - 1) // speed for p in piles)

    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        if hours_needed(mid) <= h:
            hi = mid          # mid საკმარისია — ვცადოთ უფრო ნელა
        else:
            lo = mid + 1      # mid არ კმარა — უფრო სწრაფად უნდა
    return lo

ეს ის მაგალითია, სადაც ორობითი ძებნა მასივს კი არა, არამედ „პასუხთა სივრცეს" ეძებს — k-ს 1-დან max(piles)-მდე. ვამოწმებთ: „საკმარისია თუ არა ეს სისწრაფე?" — და ეს კითხვა მონოტონურია (თუ k კმარა, ყველა k'>k-ც იკმარებს), რაც ორობითი ძებნის გამოყენების პირობაა. სირთულე: O(n · log(max(piles))), სადაც n — გროვების რაოდენობა.
