01 — ერთი წესი, დიდი შედეგი

რა არის ორობითი ძებნის ხე

ორობითი ძებნის ხე (BST) — ჩვეულებრივი ორობითი ხეა (ლექცია 10) ერთადერთი, მაგრამ გადამწყვეტი დამატებითი წესით: თითოეული კვანძისთვის, მისი მარცხენა ქვეხის ყველა მნიშვნელობა მასზე ნაკლებია, მარჯვენა ქვეხის ყველა მნიშვნელობა კი — მეტია. ეს წესი რეკურსიულად მოქმედებს ყოველ ქვეხეზეც.

BST-ის თვისება

ნებისმიერი კვანძისთვის: ყველა მარცხენა < კვანძი < ყველა მარჯვენა. სტანდარტულად, დუბლიკატები არ დაიშვება.

რატომ არის ეს ძლიერი

ეს ერთი წესი გვაძლევს ორობითი ძებნის (ლექცია 3) იმავე „განახევრების" ლოგიკას — უბრალოდ მასივის ნაცვლად, ხის სტრუქტურაზე.

🔗

პირდაპირი კავშირი ლექცია 10-თან: გახსოვთ, რომ Inorder Traversal-ს BST-ზე განსაკუთრებული მნიშვნელობა მივანიჭეთ? ახლა ვხედავთ რატომ — BST-ის განსაზღვრება თავად უზრუნველყოფს, რომ Inorder შემოვლა ყოველთვის დააბრუნებს მონაცემებს ზრდადობით დალაგებული თანმიმდევრობით. ეს არაა დამთხვევა — ეს BST-ის განმსაზღვრელი შედეგია.

02 — შეჯამება

დადებითი და უარყოფითი მხარეები

✅

დადებითი

ეფექტური ძებნა — O(log n) საშუალო შემთხვევაში; მონაცემი ბუნებრივად დალაგებულია (Inorder-ით ადვილად მისაწვდომი); დინამიური ჩასმა/წაშლა ეფექტურია; დაბალანსებულ BST-ებს ლოგარითმული სიმაღლე აქვთ.

⚠️

უარყოფითი

უარეს შემთხვევაში (თანმიმდევრულად ჩასმული მონაცემი) სირთულე ხდება O(n) — ხე „გადაგრძელდება" ერთ მიმართულებაში, ფაქტობრივად ბმულ სიად გადაიქცევა; დამატებითი მეხსიერება მაჩვენებლებისთვის; ფუნქციონალი შეზღუდულია ძებნა/ჩასმა/წაშლაზე.

⚠️

უარესი შემთხვევის კონკრეტული მაგალითი: თუ მონაცემი ქრონოლოგიურად, უკვე დალაგებული სახით ჩაისმევა (მაგ. 1, 2, 3, 4, 5 თანმიმდევრობით), თითოეული ახალი კვანძი ხდება წინას მარჯვენა შვილი — ხე იქცევა სრულიად „გადახრილ", ერთმხრივ ჯაჭვად, სიმაღლით n. ეს ზუსტად ის პრობლემაა, რასაც AVL ხეები (ლექცია 15) აგვარებენ — თვითდაბალანსების მექანიზმით.

03 — ჩასმა

ჩასმა BST-ში

ახალი კვანძი ყოველთვის ისმევა ფოთლის პოზიციაზე — ვიწყებთ root-იდან და ვადარებთ მნიშვნელობებს, სანამ ცარიელ ადგილს არ მივაღწევთ.

bst_insert.py
def insert(root: "Node", key) -> "Node":
    if root is None:
        return Node(key)
    if root.data == key:
        return root                          # დუბლიკატები არ დაიშვება
    if key < root.data:
        root.left = insert(root.left, key)
    else:
        root.right = insert(root.right, key)
    return root
🔍

შესწორება ორიგინალ მასალასთან შედარებით: ორიგინალ სლაიდებში ჩასმის ფუნქცია იყენებდა ატრიბუტს root.val, ხოლო წაშლისა და Tree Sort-ის ფუნქციები — root.key-ს. ეს შეუსაბამობაა — ერთი და იგივე Node კლასის ორი განსხვავებული ატრიბუტის სახელი ერთმანეთს ეწინააღმდეგება, რაც კოდს გაუშვებადს გახდიდა, ერთად რომ გამოგვეყენებინა. გავაერთგვაროვნეთ ყველა ფუნქცია data-ზე — ლექცია 10-12-ის Node კლასის იმავე კონვენციით.

შემთხვევასირთულე
საშუალო (დაბალანსებული ხე)O(log n)
უარესი (გადახრილი ხე)O(n)
04 — BST-ის მთავარი უპირატესობა

ძებნა BST-ში

ზუსტად იგივე „შედარება და გადაწყვეტილება" ლოგიკა, რაც ჩასმაში — უბრალოდ ახალი კვანძის დამატების ნაცვლად, ვეძებთ არსებულს.

def search(root: "Node", key):
    if root is None or root.data == key:
        return root
    if key < root.data:
        return search(root.left, key)
    return search(root.right, key)
🎯

ეს არის ორობითი ძებნის (ლექცია 3) ხის ვერსია: დალაგებულ მასივში ორობითი ძებნა ყოველ ნაბიჯზე შუა ელემენტს ამოწმებს და ნახევარს გამორიცხავს. BST-ში იგივე ხდება — უბრალოდ „შუა ელემენტი" უკვე ცალკე კვანძადაა შენახული, და მარცხენა/მარჯვენა „ნახევრები" უკვე ცალკე ქვეხეებადაა ორგანიზებული. ამიტომაცაა სირთულე იგივე — O(log n) დაბალანსებულ ხეზე.

05 — სცადეთ თავად

ააგეთ და მოძებნეთ საკუთარი BST

ჩაწერეთ რიცხვები — თანმიმდევრულად ჩაისმევა BST-ის წესის დაცვით. შემდეგ სცადეთ ძებნა და ნახეთ, რომელი გზა გაივლის ალგორითმმა root-იდან.

ოქროსფერი, წყვეტილი ჩარჩო — ძებნის გზაზე მდგომი კვანძი. მწვანე — ნაპოვნია. წითელი — იქ, სადაც ძებნამ დაადგინა, რომ ელემენტი არ არსებობს.

06 — ყველაზე რთული ოპერაცია

წაშლა BST-დან

წაშლა სამ ცალკეულ შემთხვევად იყოფა:

1. ფოთლოვანი კვანძი

არცერთი შვილი არ ჰყავს — უბრალოდ ვშლით, მშობლის შესაბამის left/right-ს None-ზე ვაყენებთ.

2. ერთი შვილი

წასაშლელი კვანძის ადგილს იკავებს მისი ერთადერთი შვილი.

3. ორი შვილი — ყველაზე რთული შემთხვევა

თუ წასაშლელ კვანძს ორივე შვილი ჰყავს, პირდაპირი წაშლა შეუძლებელია — ხე „დაიშლებოდა" ორ ცალკე ნაწილად. ამის ნაცვლად:

  1. ვპოულობთ inorder successor-ს — უმცირეს მნიშვნელობას წასაშლელი კვანძის მარჯვენა ქვეხეში (ანუ, უკიდურესად მარცხენა კვანძი იმ ქვეხეში).
  2. ამ successor-ის მონაცემს ვაკოპირებთ წასაშლელი კვანძის ადგილას.
  3. ვშლით საწყის successor-ს მისი თავდაპირველი პოზიციიდან — ეს უკვე უფრო მარტივი შემთხვევაა (successor-ს არასდროს აქვს მარცხენა შვილი).
bst_delete.py
def get_successor(root: "Node") -> "Node":
    """უმცირესი მნიშვნელობის კვანძი root-ის მარჯვენა ქვეხეში."""
    curr = root.right
    while curr and curr.left:
        curr = curr.left
    return curr

def delete_node(root: "Node", key) -> "Node":
    if root is None:
        return root

    if root.data > key:
        root.left = delete_node(root.left, key)
    elif root.data < key:
        root.right = delete_node(root.right, key)
    else:
        # ვიპოვეთ წასაშლელი კვანძი
        if root.left is None:
            return root.right          # 0 ან მხოლოდ მარჯვენა შვილი
        if root.right is None:
            return root.left           # მხოლოდ მარცხენა შვილი

        # ორი შვილი — ვცვლით inorder successor-ის მონაცემით
        succ = get_successor(root)
        root.data = succ.data
        root.right = delete_node(root.right, succ.data)

    return root
🔍

დამატებითი შესწორება: ორიგინალი Tree Sort-ის ჩასმის კოდი იყენებდა if (root == None):-ს — ზუსტად იგივე == vs is საკითხი, რასაც ლექცია 10-ში Postorder-ის მაგალითზე შევხვდით. ყველა ფუნქცია აქ თანმიმდევრულად იყენებს is None-ს.

07 — გამოყენება

დალაგება BST-ის საშუალებით (Tree Sort)

Tree Sort პირდაპირ იყენებს BST-ის მთავარ თვისებას: (1) ავაშენოთ BST მასივის ელემენტებისგან, (2) შევასრულოთ Inorder Traversal — შედეგი ავტომატურად დალაგებულია.

def inorder(root: "Node", result: list) -> None:
    if root is not None:
        inorder(root.left, result)
        result.append(root.data)
        inorder(root.right, result)

def tree_sort(arr: list) -> list:
    root = None
    for value in arr:
        root = insert(root, value)

    result = []
    inorder(root, result)
    return result
🔍

დამატებითი გაწმენდა: ორიგინალი treeins/insert ფუნქციები იყენებდნენ global root-ს — გლობალურ, ფუნქციის გარეთ არსებულ ცვლადს, რომელსაც ფუნქცია მდუმარედ ცვლიდა. ეს არღვევს კურსის განმავლობაში დამკვიდრებულ პატერნს (ბმული სია, ხე — ყველგან ახალ root/head-ს ვაბრუნებდით, გლობალურ მდგომარეობას ვერიდებოდით): გლობალური ცვლადები ართულებენ ტესტირებას და შეცდომების პოვნას დიდ პროგრამებში. ზემოთ მოცემული ვერსია root-ს ლოკალურად, ცალსახად აბრუნებს — ისევე, როგორც ამას ვაკეთებდით ლექცია 7-9-ის ბმული სიის ფუნქციებში.

შემთხვევადროითი სირთულე
საშუალოO(n log n)
უარესი (თანმიმდევრული შემავალი)O(n²)

სივრცითი სირთულე: O(n) — თავად BST-ის აგებას სჭირდება ეს სივრცე. ეს განასხვავებს Tree Sort-ს Heap Sort-ისგან (ლექცია 12), რომელიც O(log n)-ში, თითქმის in-place მუშაობდა.

08 — რეალურ სამყაროში

სად მუშაობს BST რეალურად

🗄️

მონაცემთა ბაზის ინდექსები

B-Tree და B+Tree ინდექსები (MySQL, PostgreSQL) BST-ის განზოგადებაა — თითოეულ კვანძს ერთზე მეტი გასაღები აქვს, რაც დისკზე წვდომას ამცირებს, მაგრამ ძირითადი პრინციპი იგივეა.

📚

TreeMap / TreeSet

Java-ს TreeMap/TreeSet და C++-ის std::map/std::set დაბალანსებულ BST-ებზეა აგებული (წითელ-შავი ხეები) — გვაძლევენ დალაგებულ, ეფექტურ key-value საცავს.

📁

ფაილური სისტემები

ზოგიერთი ფაილური სისტემა BST-ის მსგავს სტრუქტურებს იყენებს ფაილების სწრაფი მოძიებისთვის სახელის მიხედვით.

🎮

თამაშების დეველოპმენტი

სივრცითი ინდექსაცია (obiექტების სწრაფად პოვნა კოორდინატის მიხედვით) ხშირად იყენებს BST-ის იდეებზე დაფუძნებულ სტრუქტურებს (მაგ. k-d ხეები).

09 — სავარჯიშოები

დამატებითი პრაქტიკა

დღეს ნასწავლი ტექნიკების ბუნებრივი გაგრძელება — BST-ზე დამატებით ამოცანებს კურსის მომდევნო ეტაპზე ღრმად შევეხებით.

Range Sum of BST მარტივი

დააბრუნეთ ყველა იმ კვანძის მონაცემის ჯამი, რომლებიც [low, high] დიაპაზონშია (LeetCode 938).

def range_sum_bst(root: "Node", low: int, high: int) -> int:
    if root is None:
        return 0
    if root.data < low:                      # მთელი მარცხენა ქვეხე ძალიან პატარაა
        return range_sum_bst(root.right, low, high)
    if root.data > high:                      # მთელი მარჯვენა ქვეხე ძალიან დიდია
        return range_sum_bst(root.left, low, high)
    return (root.data
            + range_sum_bst(root.left, low, high)
            + range_sum_bst(root.right, low, high))

BST-ის თვისების პირდაპირი გამოყენება: თუ მიმდინარე კვანძი დიაპაზონს გარეთაა, BST-ის წესის წყალობით ზუსტად ვიცით, რომელი მთელი ქვეხე შეგვიძლია სრულად გამოვტოვოთ — ჩვეულებრივ ორობით ხეზე ეს შეუძლებელი იქნებოდა.

Kth Smallest Element in a BST საშუალო

იპოვეთ k-ურად უმცირესი მნიშვნელობა BST-ში (LeetCode 230).

def kth_smallest(root: "Node", k: int):
    stack = []
    curr = root
    count = 0
    while stack or curr:
        while curr:
            stack.append(curr)
            curr = curr.left
        curr = stack.pop()
        count += 1
        if count == k:
            return curr.data
        curr = curr.right
    return None

დღევანდელი Inorder-ის თვისების პირდაპირი გამოყენება: ვინაიდან Inorder Traversal ყოველთვის აბრუნებს დალაგებულ თანმიმდევრობას, k-ურად უმცირესი უბრალოდ Inorder-ის k-ური ელემენტია. აქ გამოყენებულია იტერაციული Inorder (მკაფიო stack-ით, ლექცია 11-ის „რეკურსია vs იტერაცია" თემის გაგრძელება) — შეგვიძლია ადრე შევჩერდეთ, როგორც კი k-ურ ელემენტს მივაღწევთ, სრული შემოვლის დასრულების მოლოდინის გარეშე.

Recover Binary Search Tree რთული

BST-ში ორი კვანძის მონაცემი შემთხვევით არის გაცვლილი, რის გამოც ხე აღარ არის ვალიდური BST. გამოასწორეთ ხე ადგილზევე (in-place), O(1) დამატებითი სივრცით (LeetCode 99).

def recover_tree(root: "Node") -> None:
    first = second = prev = None
    stack = []
    curr = root

    while stack or curr:
        while curr:
            stack.append(curr)
            curr = curr.left
        curr = stack.pop()

        # ვალიდურ BST-ში, Inorder-ისას ყოველი შემდეგი მნიშვნელობა
        # წინაზე მეტი უნდა იყოს — დარღვევა ავლენს "ეჭვმიტანილ" კვანძებს
        if prev and prev.data > curr.data:
            if first is None:
                first = prev
            second = curr

        prev = curr
        curr = curr.right

    first.data, second.data = second.data, first.data

საკვანძო დაკვირვება: ვალიდურ BST-ში Inorder თანმიმდევრობა მკაცრად ზრდადია — ორი გაცვლილი კვანძი ამ თანმიმდევრობაში ან ერთ, ან ორ ადგილას შექმნის „დარღვევას" (წინა ელემენტი > შემდეგი). პირველი დარღვევისას ვინახავთ „საეჭვო" წყვილის პირველ წევრს (first); ნებისმიერ შემდეგ დარღვევაში ვაახლებთ მეორეს (second) — ეს ორი შემთხვევა ფარავს როგორც მეზობელი, ისე შორეული კვანძების გაცვლას.
