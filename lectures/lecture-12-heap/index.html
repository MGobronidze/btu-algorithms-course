01 — ახალი კონცეფცია

რა არის გროვა

გროვა (heap) სპეციალური ხის ტიპის მონაცემთა სტრუქტურაა ორი განმსაზღვრელი თვისებით: (1) ის სრული ორობითი ხეა (Complete Binary Tree) და (2) ის მიჰყვება ან Max-Heap-ის, ან Min-Heap-ის წესს.

Max-Heap

root-ის მნიშვნელობა ყოველთვის ≥ ორივე შვილისა — და ეს წესი მოქმედებს რეკურსიულად ყველა ქვეხეზეც.

Min-Heap

root-ის მნიშვნელობა ყოველთვის ≤ ორივე შვილისა — იგივე რეკურსიული წესი, საწინააღმდეგო მიმართულებით.

🌳

„Complete" — არა „Full": სრული ორობითი ხე ნიშნავს, რომ ყველა დონე შევსებულია, გარდა შესაძლოა ბოლოსი — და ბოლო დონეც მარცხნიდან მარჯვნივ, უფსკრულების გარეშე ივსება. ეს ზუსტად ის თვისებაა, რაც გროვას საშუალებას აძლევს იცხოვროს უბრალო მასივში, საჩვენებლების (left/right) გარეშეც — ლექცია 10-ის ხის კვანძებისგან განსხვავებით.

მასივი, როგორც ხე

თუ ხის კვანძებს ინდექსით 0-დან დავნომრავთ, ორი მარტივი ფორმულა გვაძლევს მთელ სტრუქტურას — მაჩვენებლების საჭიროების გარეშე:

  • მარცხენა შვილი: 2·i + 1
  • მარჯვენა შვილი: 2·i + 2
  • მშობელი: (i − 1) // 2

ეს არის ვალიდური Max-Heap — root (16) ყველაზე დიდია, და თითოეული მშობელი ≥ თავისი შვილებისა.

02 — რატომ არის ეს სასარგებლო

გროვის თვისებები

⚡

უმთავრესი უპირატესობა: მინიმალური (ან მაქსიმალური) ელემენტი ყოველთვის root-შია — რაც წვდომას მასზე O(1)-ში ხდის შესაძლებელს. ეს არის მთავარი მიზეზი, რატომაც არჩევენ heap-ს, როცა ხშირად გჭირდებათ „ამჟამინდელი უდიდესი/უმცირესი" ელემენტის სწრაფად პოვნა — priority queue-ს კლასიკური გამოყენების შემთხვევა.

ჩასმისას: ახალი ელემენტი თავსდება მასივის ბოლოს (სრული ხის შემდეგი თავისუფალი პოზიცია), შემდეგ „ადის ზემოთ" (sift up), სანამ heap-ის თვისება არ აღდგება.

წაშლისას: root იცვლება ბოლო ელემენტით, ეს ელემენტი „ეშვება ქვემოთ" (sift down / heapify), სანამ heap-ის თვისება არ აღდგება.

03 — ცენტრალური ოპერაცია

Heapify

Heapify — პროცესია, რომელიც კვანძების გადანაწილებით აღადგენს heap-ის თვისებას, მას შემდეგ რაც რაიმე ცვლილება მოხდება (ჩასმა, წაშლა, ან საწყისი აგება).

max_heapify.py
def MaxHeapify(self, i: int) -> None:
    l = self.lChild(i)
    r = self.rChild(i)
    largest = i

    if l < self.heapSize and self.arr[l] > self.arr[i]:
        largest = l
    if r < self.heapSize and self.arr[r] > self.arr[largest]:
        largest = r

    if largest != i:
        self.arr[i], self.arr[largest] = self.arr[largest], self.arr[i]
        self.MaxHeapify(largest)   # რეკურსიულად ვაგრძელებთ ქვემოთ

ინტუიცია: ვამოწმებთ, არის თუ არა i-ური კვანძის რომელიმე შვილი მასზე დიდი. თუ კი — ვცვლით ადგილებს უდიდეს შვილთან და ვიმეორებთ იმ პოზიციაზე, სადაც ელემენტი ახლა აღმოჩნდა. ეს გრძელდება, სანამ ელემენტი „არ ჩერდება" თავის სწორ ადგილას.

დროითი სირთულერატომ
O(log n)თითოეულ ნაბიჯზე მაქსიმუმ ერთი დონით ვეშვებით ქვემოთ — ხის სიმაღლეა log n
04 — სრული იმპლემენტაცია

MaxHeap კლასი

max_heap.py
class MaxHeap:
    def __init__(self, max_size: int):
        self.maxSize = max_size
        self.arr = [0] * max_size
        self.heapSize = 0

    def parent(self, i: int) -> int:
        return (i - 1) // 2

    def lChild(self, i: int) -> int:
        return 2 * i + 1

    def rChild(self, i: int) -> int:
        return 2 * i + 2

insertKey — ჩასმა

def insertKey(self, x) -> None:
    if self.heapSize == self.maxSize:
        print("Overflow: Could not insertKey")
        return
    self.heapSize += 1
    i = self.heapSize - 1
    self.arr[i] = x
    # ავდივართ ზემოთ, სანამ heap-ის თვისება არ აღდგება
    while i != 0 and self.arr[self.parent(i)] < self.arr[i]:
        self.arr[i], self.arr[self.parent(i)] = self.arr[self.parent(i)], self.arr[i]
        i = self.parent(i)

removeMax — root-ის ამოღება

def removeMax(self):
    if self.heapSize <= 0:
        return None
    if self.heapSize == 1:
        self.heapSize -= 1
        return self.arr[0]

    root = self.arr[0]
    self.arr[0] = self.arr[self.heapSize - 1]   # ბოლო ელემენტი root-ის ადგილას
    self.heapSize -= 1
    self.MaxHeapify(0)                          # თვისების აღდგენა
    return root

increaseKey, getMax, curSize, deleteKey

def increaseKey(self, i: int, newVal) -> None:
    if newVal < self.arr[i]:
        raise ValueError("newVal არ შეიძლება იყოს მიმდინარე მნიშვნელობაზე ნაკლები")
    self.arr[i] = newVal
    while i != 0 and self.arr[self.parent(i)] < self.arr[i]:
        self.arr[i], self.arr[self.parent(i)] = self.arr[self.parent(i)], self.arr[i]
        i = self.parent(i)

def getMax(self):
    return self.arr[0]                # O(1) — root ყოველთვის მაქსიმუმია

def curSize(self) -> int:
    return self.heapSize

def deleteKey(self, i: int) -> None:
    # ვზრდით უსასრულობამდე, რომ root-ში "ავიდეს", მერე ვშლით root-ს
    self.increaseKey(i, float("inf"))
    self.removeMax()
🔍

დამატება ორიგინალ მასალასთან შედარებით: საწყისი increaseKey არ ამოწმებდა, რომ newVal მართლაც მეტია მიმდინარე მნიშვნელობაზე. სახელწოდება „increase" ცალსახად გულისხმობს მხოლოდ ზრდას — მაგრამ თუ ვინმე შემთხვევით უფრო პატარა მნიშვნელობას გადასცემდა, ფუნქცია მაინც შეასრულებდა „ავდივართ ზემოთ" ციკლს (რომელიც არაფერს იზამდა), თუმცა arr-ში დარჩებოდა არასწორად ჩასმული, ნაკლები მნიშვნელობა, რომელიც ქვემოთ აღარ შემოწმდებოდა — რღვევს heap-ის თვისებას მდუმარედ, შეცდომის გარეშე. დავამატეთ ვალიდაცია, რომელიც ამ საშიშ სცენარს თავიდანვე ხმამაღლა (ValueError-ით) აღკვეთს.

05 — გამოყენება

დალაგება გროვის საშუალებით (Heap Sort)

Heap Sort შედარებაზე დაფუძნებული დალაგების ტექნიკაა, რომელიც პირდაპირ იყენებს heap-ის სტრუქტურას — თავად მასივის შიგნით, დამატებითი მასივის გარეშე.

  1. Build heap: მთელი მასივი გარდაიქმნება max-heap-ად — heapify გამოიძახება ბოლოდან-პირველი შიდა კვანძიდან root-მდე.
  2. ამოღება: root (ამჟამინდელი მაქსიმუმი) იცვლება heap-ის ბოლო ელემენტთან — ეს ათავსებს მაქსიმუმს მის საბოლოო, სწორ პოზიციაზე.
  3. შემცირება: heap-ის „ზომა" მცირდება 1-ით (ბოლო ელემენტი — უკვე დალაგებული — აღარ ითვლება heap-ის ნაწილად, თუმცა ფიზიკურად მასივშივე რჩება).
  4. გამეორება: ვიძახებთ heapify-ს ახალ root-ზე და ვიმეორებთ, სანამ heap-ში ერთი ელემენტი აღარ დარჩება.
heap_sort.py
def heapify(arr: list, n: int, i: int) -> None:
    """i-ური კვანძის ქვეხეს heap-ის თვისებას უბრუნებს — arr[:n] ფარგლებში."""
    largest = i
    l, r = 2 * i + 1, 2 * i + 2

    if l < n and arr[l] > arr[largest]:
        largest = l
    if r < n and arr[r] > arr[largest]:
        largest = r

    if largest != i:
        arr[i], arr[largest] = arr[largest], arr[i]
        heapify(arr, n, largest)

def heap_sort(arr: list) -> None:
    n = len(arr)

    # 1. მთელი მასივის გარდაქმნა max-heap-ად
    for i in range(n // 2 - 1, -1, -1):
        heapify(arr, n, i)

    # 2. ერთი-ერთზე ამოვიღოთ მაქსიმუმი და ჩავსვათ საბოლოო ადგილას
    for i in range(n - 1, 0, -1):
        arr[0], arr[i] = arr[i], arr[0]   # root → i-ურ (ამჟამინდელი ბოლო) პოზიციაზე
        heapify(arr, i, 0)                 # heap-ის თვისების აღდგენა შემცირებულ ზომაზე
💡

ეს არის MaxHeapify-ის იგივე ლოგიკა, უბრალოდ self-ის გარეშე: heap_sort ცალკე, კლასის-გარეშე ფუნქციად იყენებს იგივე heapify იდეას — n პარამეტრი აქ თამაშობს self.heapSize-ის როლს, ხელოვნურად „ამცირებს" heap-ის ხილულ ზომას, მასივის ფაქტობრივი შემცირების გარეშე.

06 — სცადეთ თავად

Heap Sort ნაბიჯ-ნაბიჯ

დააჭირეთ „შემდეგი ნაბიჯს" — ჯერ ნახავთ Build Heap ფაზას (მასივი გარდაიქმნება max-heap-ად), შემდეგ ამოღების ფაზას (თითოეული მაქსიმუმი გადადის თავის საბოლოო, დალაგებულ პოზიციაზე).

მწვანე — უკვე თავის საბოლოო, დალაგებულ პოზიციაზე მდგომი ელემენტები. ოქროსფერი — heapify-ის მიმდინარე root. ლურჯი — swap-ის მონაწილე წყვილი.

სივრცითი სირთულე Heap Sort-ისთვის: O(log n) (რეკურსიული heapify-ს call stack) — Merge Sort-ის O(n)-ისგან განსხვავებით, Heap Sort in-place მუშაობს, დამატებითი მასივის გარეშე.

🤔

საინტერესო დაკვირვება — Build Heap არის O(n), არა O(n log n): თუმცა ერთი heapify-ის გამოძახება O(log n)-ია და მას n/2-ჯერ ვიძახებთ (რაც პირველი შეხედვით O(n log n)-ს მოგვცემდა), მკაცრი მათემატიკური ანალიზი აჩვენებს, რომ ჯამური სირთულეა სინამდვილეში O(n) — რადგან ხის ქვედა დონეებზე (სადაც ყველაზე მეტი კვანძია) heapify-ს ძალიან მცირე სამუშაოს აკეთებინებთ, და მხოლოდ ცოტა კვანძს root-თან ახლოს სჭირდება ბევრი ნაბიჯი.

08 — რეალურ სამყაროში

სად მუშაობს გროვა რეალურად

🐍

Python-ის heapq

Python-ის ჩაშენებული heapq მოდული ზუსტად დღეს ნასწავლ ალგორითმებს ახორციელებს — heapq.heappush/heappop — უბრალო, დინამიურ სიაზე მუშაობს, maxSize-ის წინასწარი განსაზღვრის გარეშე. Production კოდში თითქმის არასდროს წერთ საკუთარ heap-ს ნულიდან — იყენებთ ამ მოდულს.

⏱️

Priority Queue — დავალებების დაგეგმვა

ოპერაციული სისტემების პროცესების დაგეგმვა (process scheduling), ღონისძიებების სიმულაცია (event-driven simulation) — ყველგან, სადაც „შემდეგი, ყველაზე პრიორიტეტული დავალება" სწრაფად უნდა მოიძებნოს, heap დგას საფუძვლად.

🗺️

Dijkstra-ს ალგორითმი

უმოკლესი გზის პოვნის კლასიკური ალგორითმი (გრაფებზე, კურსის მომდევნო ეტაპებში) იყენებს min-heap-ს, რომ ყოველთვის სწრაფად აირჩიოს შემდეგი, „ყველაზე ახლოს" მდგომი წვერო.

K-way Merge

რამდენიმე უკვე დალაგებული ნაკადის (მაგ. სხვადასხვა სერვერიდან მიღებული შედეგების) გაერთიანება ერთ დალაგებულ თანმიმდევრობად — heap საშუალებას გვაძლევს ყოველთვის სწრაფად ვიპოვოთ შემდეგი უმცირესი ელემენტი ყველა ნაკადს შორის.

09 — პრაქტიკა

სავარჯიშოები — Python-ის heapq-ით

დღეს ნასწავლი პრინციპები Python-ის ჩაშენებული მოდულით.

Kth Largest Element in a Stream მარტივი

შექმენით სტრუქტურა, რომელიც მუდმივად აბრუნებს k-ურ უდიდეს ელემენტს, მაშინაც კი, როცა ახალი რიცხვები მუდმივად „მოედინება" (LeetCode 703).

import heapq

class KthLargest:
    def __init__(self, k: int, nums: list):
        self.k = k
        self.heap = nums[:]
        heapq.heapify(self.heap)
        while len(self.heap) > k:
            heapq.heappop(self.heap)

    def add(self, val: int) -> int:
        heapq.heappush(self.heap, val)
        if len(self.heap) > self.k:
            heapq.heappop(self.heap)
        return self.heap[0]

ხრიკი: Python-ის heapq ნაგულისხმევად min-heap-ია. თუ ზომაზე k-ით შემოვსაზღვრავთ (ზედმეტს ვშლით), მინ-heap-ის root ყოველთვის იქნება k-ური უდიდესი ელემენტი — ელეგანტური გზა max-ის მოსაძებნად min-heap-ით.

Top K Frequent Elements საშუალო

დააბრუნეთ k ყველაზე ხშირად განმეორებადი ელემენტი მასივში (LeetCode 347).

import heapq
from collections import Counter

def top_k_frequent(nums: list, k: int) -> list:
    counts = Counter(nums)
    return [item for item, _ in heapq.nlargest(k, counts.items(), key=lambda pair: pair[1])]

heapq.nlargest(k, ...) შიგნით სწორედ heap-ს იყენებს — ინახავს მხოლოდ k ზომის heap-ს მთელი მონაცემის ნაცვლად, რაც O(n log k)-ს იძლევა სრული დალაგების O(n log n)-ის ნაცვლად.

Merge K Sorted Lists რთული

მოცემულია k დალაგებული ბმული სია (ლექცია 7-9-ის თემა!) — გააერთიანეთ ერთ დალაგებულ სიად (LeetCode 23).

import heapq

def merge_k_lists(lists: list) -> "Node":
    heap = []
    for i, node in enumerate(lists):
        if node:
            heapq.heappush(heap, (node.data, i, node))

    dummy = Node(0)
    tail = dummy
    while heap:
        val, i, node = heapq.heappop(heap)
        tail.next = node
        tail = tail.next
        if node.next:
            heapq.heappush(heap, (node.next.data, i, node.next))

    return dummy.next

ეს ამოცანა აერთიანებს სამ ლექციას: ბმული სია (ლექცია 7), Merge Sort-ის ორნაკადიანი შერწყმის იდეა (ლექცია 4) — ახლა k ნაკადამდე გაფართოებული — და დღევანდელი heap. თითოეულ ნაბიჯზე heap-ში ვინახავთ k სიის ამჟამინდელ „წამყვან" კვანძებს, ვიღებთ უმცირესს (O(log k)), და მის ადგილას იმავე სიის შემდეგ კვანძს ვამატებთ. სირთულე: O(N log k), სადაც N — ყველა ელემენტის საერთო რაოდენობა — ბევრად სწრაფია, ვიდრე ყველა წყვილის ცალ-ცალკე შერწყმა (O(N·k)).
