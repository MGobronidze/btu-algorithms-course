დათვლით დალაგება და რედიქს დალაგების მეთოდი

როგორ დავალაგოთ მასივი ელემენტების შედარების გარეშე — წრფივი დროის ორი ალგორითმი, რომლებიც არღვევს O(n log n)-ის ცნობილ ზღვარს კონკრეტული, მაგრამ ხშირად გვხვდადი პირობებისთვის.

Counting Sort Radix Sort არა-შედარებითი დალაგება O(n + k) სტაბილურობა

წინა ლექციების გაგრძელება

ლექციებზე IV და V ვისწავლეთ სამი შედარებაზე დაფუძნებული დალაგების მეთოდი — insertion, merge და quick sort. სამივემ საერთო ზღვარი გვაჩვენა: ერთი წყვილის შედარება ერთი ბიტი ინფორმაციაა, და n ელემენტის ყველა შესაძლო დალაგებას (n! ვარიანტი) გასარჩევად საჭიროა სულ მცირე log₂(n!) ≈ n log n შედარება. ეს არის დამტკიცებადი ქვედა ზღვარი ნებისმიერი შედარებაზე დაფუძნებული ალგორითმისთვის.

დღევანდელი ორი ალგორითმი ამ ზღვარს არ არღვევს — ისინი უბრალოდ საერთოდ არ იყენებენ შედარებას. Counting sort და radix sort ელემენტებს პირდაპირ მათი მნიშვნელობით ალაგებენ მასივის ინდექსებად გამოყენებით, ამიტომ n log n-ის მაგივრად მივიღებთ წრფივთან ახლოს მდგომ სირთულეს — მაგრამ მხოლოდ მაშინ, როცა მონაცემებს კონკრეტული სტრუქტურა აქვთ (მცირე დიაპაზონი ან ფიქსირებული სიგრძის გასაღები).

🔗 კავშირი წინა მასალასთან

ლექცია II-ში ვნახეთ, რომ ალგორითმის სირთულე დამოკიდებულია არა მხოლოდ n-ზე, არამედ იმაზეც, რა ოპერაციებს ვუშვებთ. აქ სწორედ ეს პრინციპია საქმეში: შედარების აკრძალვით ვიღებთ სწრაფ, მაგრამ შეზღუდულ ალგორითმებს — ისინი მუშაობენ მხოლოდ მთელ რიცხვებზე (ან მათზე დაყვანად გასაღებებზე).

დათვლით დალაგება

Counting Sort არის შედარებაზე არადამოკიდებული დალაგების ალგორითმი, რომელიც განსაკუთრებით ეფექტურია, როცა შემავალი მონაცემების მნიშვნელობების დიაპაზონი (k) შედარებით მცირეა ელემენტების რაოდენობასთან (n).

იდეა მარტივია: ვთვლით, რამდენჯერ გვხვდება თითოეული უნიკალური მნიშვნელობა მასივში, შემდეგ ამ სიხშირეების გამოყენებით პირდაპირ ვანგარიშობთ, სად უნდა დადგეს თითოეული ელემენტი საბოლოო, დალაგებულ მასივში — შედარების გარეშე.

countArray[]

დამხმარე მასივი, სადაც ინდექსი = მნიშვნელობა, მნიშვნელობა = სიხშირე (მოგვიანებით — პრეფიქსული ჯამი).

პრეფიქსული ჯამი

countArray[i] = countArray[i−1] + countArray[i] — გვეუბნება, რამდენი ელემენტია ≤ i.

outputArray[]

საბოლოო დალაგებული მასივი, რომელსაც ვავსებთ inputArray-ის ბოლოდან დაწყებული იტერაციით.

ნაბიჯები

  1. ვპოულობთ inputArray-ის უდიდეს (და უმცირეს) ელემენტს — ამით ვსაზღვრავთ countArray-ის ზომას.
  2. ვქმნით countArray[]-ს, თავიდან ბოლომდე 0-ებით.
  3. ვთვლით: countArray[x]++ თითოეული x ∈ inputArray-სთვის.
  4. ვაქცევთ პრეფიქსულ ჯამად: countArray[i] += countArray[i-1].
  5. inputArray-ს ბოლოდან დასაწყისამდე ვავსებთ outputArray-ს: outputArray[countArray[x]-1] = x, შემდეგ countArray[x]--.
⚠️ რატომ ბოლოდან?

თუ inputArray-ს დასაწყისიდან გავივლიდით (i = 0, 1, 2, ...), დალაგება მაინც სწორი გამოვიდოდა, მაგრამ დაიკარგებოდა სტაბილურობა — ერთნაირი მნიშვნელობის ელემენტები საბოლოო მასივში საწყისი თანმიმდევრობის საპირისპიროდ დალაგდებოდნენ. ბოლოდან დაწყებული იტერაცია სწორედ ამის ასაცილებლადაა საჭირო.

💡 დააკვირდით

ავტომატურ რეჟიმში ნახავთ, რომ countArray-ის მნიშვნელობები ერთი-ერთის მცირდება ყოველ განთავსებაზე — ეს არის ის მექანიზმი, რომელიც ერთნაირ მნიშვნელობებს სტაბილურად, სწორი თანმიმდევრობით ანაწილებს outputArray-ში.

ალგორითმი და Python კოდი

ორიგინალი მასალის ფსევდოკოდი, გასუფთავებული და შევსებული Python 3.12+ სტილში — type hints, docstring-ი და edge-case-ების დაცვა.

def counting_sort(nums: Sequence[int]) -> list[int]:
    """სტაბილური დათვლით დალაგება. ამუშავებს უარყოფით რიცხვებსაც.

    დრო:    O(n + k), სადაც k = max(nums) - min(nums) + 1
    სივრცე: O(n + k)
    """
    if not nums:
        return []

    lo, hi = min(nums), max(nums)
    counts = [0] * (hi - lo + 1)

    for x in nums:
        counts[x - lo] += 1

    for i in range(1, len(counts)):
        counts[i] += counts[i - 1]

    result = [0] * len(nums)
    for x in reversed(nums):          # ბოლოდან — სტაბილურობისთვის
        counts[x - lo] -= 1
        result[counts[x - lo]] = x

    return result
🔍 შესწორება ორიგინალთან შედარებით

ორიგინალ სლაიდებზე countArray-ის ზომა განისაზღვრება მხოლოდ max(inputArray)+1-ით — ეს ვარაუდობს, რომ ყველა ელემენტი ≥ 0-ია. თუ მასივში გვხვდება უარყოფითი რიცხვი, countArray[num]-ზე წვდომა უარყოფითი ინდექსით მოხდება, რაც Python-ში ჩუმად „მუშაობს" (მასივს ბოლოდან კითხულობს), მაგრამ არასწორ შედეგს იძლევა — ეს გადამოწმებულია ცალკე ტესტით. ზემოთ მოცემული ვერსია იყენებს lo = min(nums)-ს წანაცვლებად, რაც უარყოფით რიცხვებსაც სწორად ამუშავებს.

🔍 ცარიელი მასივი

ორიგინალი ფსევდოკოდი max(inputArray)-ს პირდაპირ იძახებს — ცარიელ მასივზე ეს ValueError-ს ისვრის (გადამოწმებულია გაშვებით). ზემოთ დამატებული if not nums: return [] ეს ფრთხილად ამოწმებს, სანამ min/max-ს გამოვიძახებთ.

თუ k >> n (მაგალითად, ორი ელემენტიანი მასივი მნიშვნელობებით 1 და 10,000,000), countArray-ის ზომა თავად გახდება ბოლოკო — ასეთ შემთხვევაში O(n log n) შედარებითი დალაგება (merge/quick sort) სჯობს.

რედიქს დალაგების ალგორითმი

Radix Sort წრფივი დროის დალაგების ალგორითმია მთელი რიცხვებისთვის (ან ფიქსირებული სიგრძის გასაღებებისთვის) — ელემენტების პირდაპირი შედარების ნაცვლად, ისინი თანრიგ-თანრიგ, ციფრის მნიშვნელობის მიხედვით ნაწილდება.

ძირითადი იდეა: ჯერ ვალაგებთ ერთეულების ციფრის მიხედვით, მერე ათეულების, მერე ასეულების — ყოველ ჯერზე სტაბილური ქვე-დალაგებით (და counting sort ზუსტად ასეთია). ყველაზე ნაკლებად მნიშვნელოვანი ციფრიდან ყველაზე მნიშვნელოვნამდე (LSD — Least Significant Digit) გავლის შემდეგ, მასივი სრულად დალაგებულია.

🎯 რატომ უნდა იყოს ქვე-დალაგება სტაბილური?

წარმოვიდგინოთ, რომ ათეულების ციფრით ვალაგებთ და უკვე გვაქვს ორი ელემენტი ერთნაირი ათეულის ციფრით, მაგრამ განსხვავებული ერთეულის ციფრით (მაგ. 802 და 809 — ორივეს ათეულების ციფრი 0-ია). თუ ეს ნაბიჯი არასტაბილურია, მათი ერთმანეთთან შედარებითი წყობა (802 უნდა იყოს 809-ზე ადრე, რადგან ერთეულების დალაგება ეს უკვე უზრუნველყო) დაიკარგება. Radix sort-ის სისწორე მთლიანად ეყრდნობა ყოველი გავლის სტაბილურობას.

def _count_by_digit(nums: list[int], exp: int, base: int = 10) -> list[int]:
    """ერთი სტაბილური counting-sort გავლა, exp თანრიგზე (1, 10, 100, ...)."""
    counts = [0] * base
    for x in nums:
        counts[(x // exp) % base] += 1
    for i in range(1, base):
        counts[i] += counts[i - 1]

    result = [0] * len(nums)
    for x in reversed(nums):
        digit = (x // exp) % base
        counts[digit] -= 1
        result[counts[digit]] = x
    return result


def radix_sort(nums: Sequence[int], base: int = 10) -> list[int]:
    """LSD Radix Sort. მხოლოდ არაუარყოფითი მთელი რიცხვებისთვის."""
    if not nums:
        return []

    result = list(nums)
    max_val = max(result)
    exp = 1
    while max_val // exp > 0:      # მთელრიცხვური გაყოფა — არა float
        result = _count_by_digit(result, exp, base)
        exp *= base
    return result

ორიგინალი კოდი გამეორების პირობად იყენებდა max1 / exp >= 1 — Python 3-ში / ყოველთვის float-ს აბრუნებს. მცირე რიცხვებზე ეს მუშაობს, მაგრამ ძალიან დიდი მთელი რიცხვებისთვის (რომლებსაც float ვეღარ იტევს ზუსტად) ეს კოდი OverflowError-ს ისვრის — გადამოწმებულია გაშვებით (10**400 / 1 უკვე ავარიულდება). გასწორებული ვერსია იყენებს მთელრიცხვურ გაყოფას //-ს, რომელსაც ზომის შეზღუდვა არ აქვს.
