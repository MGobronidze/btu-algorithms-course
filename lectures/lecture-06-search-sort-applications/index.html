02 — ამოცანა 1

Search Insert Position

ამოცანა: მოცემულია დალაგებული მასივი და რიცხვი target. თუ target მასივშია — დააბრუნეთ მისი ინდექსი. თუ არა — დააბრუნეთ ინდექსი, სადაც ის უნდა ჩაისვას, რომ მასივი დალაგებული დარჩეს.

🔗

ეს ამოცანა უკვე ამოვხსენით ლექცია 3-ის სავარჯიშოებში (LeetCode 35) — თუ გამოტოვეთ, კარგი მომენტია დასაბრუნებლად. საკვანძო დაკვირვება: მასივი დალაგებულია → ეს ორობითი ძებნის სიგნალია.

search_insert.py
def search_insert(nums: list, target: int) -> int:
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return left   # target ვერ მოიძებნა — left არის სწორი ჩასმის წერტილი
💡

რატომ სწორედ left: ციკლის დასრულებისას left > right-ია, და ეს ორი მაჩვენებელი „გადაცდნენ" ერთმანეთს ზუსტად იმ წერტილში, სადაც target „ჯდება" — ყველა ელემენტი left-მდე მასზე პატარაა, ყველა right-იდან (ანუ left-იდანვე) — მასზე დიდი.

სირთულე: O(log n) დროში, O(1) სივრცეში.

03 — ამოცანა 2

Search a 2D Matrix

ამოცანა: მოცემულია მატრიცა, სადაც თითოეული სტრიქონი და თითოეული სვეტი ზრდადობითაა დალაგებული. დავადგინოთ, გვხვდება თუ არა target მატრიცაში.

⚠️

ორი განსხვავებული ამოცანა ერთი სახელით: LeetCode-ზე ორი მსგავსი ამოცანაა ამ სახელით. LeetCode 74-ს დამატებით პირობა აქვს — თითოეული სტრიქონის პირველი რიცხვი მეტია წინა სტრიქონის ბოლო რიცხვზე, ანუ მთელი მატრიცა შეიძლება „გაიშალოს" ერთ დალაგებულ მასივად. LeetCode 240-ს (და ამ ლექციის ალგორითმს) ეს დამატებითი პირობა არ სჭირდება — მხოლოდ სტრიქონები და სვეტები ცალ-ცალკეა დალაგებული. ეს განსხვავება მნიშვნელოვანია: რაც უფრო ძლიერია პირობა, მით უფრო სწრაფი ალგორითმის აგება შეგვიძლია — კლასიკური გაკვეთილი იმისა, თუ რატომაა ამოცანის ზუსტი პირობების წაკითხვა გადამწყვეტი.

ზოგადი ამოხსნა — „კიბის" ძებნა (LeetCode 240)

დავიწყოთ მარჯვენა ზედა კუთხიდან. ეს კუთხე უნიკალურია: მისი მარცხნივ ყველაფერი პატარაა, მისი ქვემოთ ყველაფერი — დიდი. ამიტომ ერთი შედარებით ყოველთვის შეგვიძლია მთელი სტრიქონის ან სვეტის გამორიცხვა:

search_matrix.py
def search_matrix(matrix: list, target: int) -> bool:
    if not matrix or not matrix[0]:
        return False
    rows, cols = len(matrix), len(matrix[0])
    row, col = 0, cols - 1        # ვიწყებთ მარჯვენა ზედა კუთხიდან
    while row < rows and col >= 0:
        if matrix[row][col] == target:
            return True
        elif matrix[row][col] > target:
            col -= 1               # ძალიან დიდია — მთელი სვეტი გამოირიცხა
        else:
            row += 1                # ძალიან პატარაა — მთელი სტრიქონი გამოირიცხა
    return False

ოქროსფერი — მიმდინარე უჯრედი. ჩამქრალი — უკვე გამორიცხული სტრიქონი/სვეტი. თითოეულ ნაბიჯზე ან მთელი სტრიქონი, ან მთელი სვეტი „ქრება" — ამიტომაა ალგორითმი O(n+m)-ში.

მიდგომაპირობასირთულე
„კიბის" ძებნა (ზემოთ)სტრიქონები და სვეტები ცალ-ცალკე დალაგებულიO(n + m)
ერთი ორობითი ძებნამთელი მატრიცა „ვირტუალურად" ერთი დალაგებული მასივია (LeetCode 74)O(log(n·m))

თუ LeetCode 74-ის უფრო ძლიერი პირობა გვაქვს, ინდექსის გადაქცევა (row, col)-დან 1D-ში ტრივიალურია: row = mid // cols, col = mid % cols — შედეგად სრული ორობითი ძებნის სიჩქარეს ვიღებთ, O(n+m)-ის ნაცვლად O(log(n·m)).

04 — ამოცანა 3

Missing Number

ამოცანა: მოცემულია n განსხვავებული რიცხვი დიაპაზონიდან [0, n] — ანუ სულ n+1 შესაძლო მნიშვნელობიდან ზუსტად ერთია გამოტოვებული. იპოვეთ გამოტოვებული რიცხვი.

🧮

საკვანძო დაკვირვება: არც კი გვჭირდება მასივის დალაგება ან ძებნა! თუ ვიცით, რა უნდა იყოს ჯამი დიაპაზონის ყველა რიცხვისთვის (ცნობილი ფორმულით), და გამოვაკლებთ რეალურ ჯამს — სხვაობა ზუსტად გამოტოვებული რიცხვი იქნება.

missing_number.py
def missing_number(nums: list) -> int:
    n = len(nums)
    expected_sum = n * (n + 1) // 2   # 0-დან n-მდე ჯამის ფორმულა
    actual_sum = sum(nums)
    return expected_sum - actual_sum

სირთულე: O(n) დროში (ერთი გავლა sum()-ისთვის), O(1) სივრცეში.

🔍

ინდუსტრიული ალტერნატივა — XOR ტექნიკა: ენებში, სადაც მთელი რიცხვის ზომა შეზღუდულია (Java, C++), დიდ n-ზე n * (n+1) შეიძლება overflow-ს იწვევდეს, სანამ 2-ზე გაიყოფოდეს. Python-ს ეს პრობლემა არ აქვს (მთელი რიცხვები თავისთავად იზრდება), მაგრამ ღირს იცოდეთ ალტერნატივა, რომელიც ამ პრობლემას სრულად გვერდს უვლის — XOR ოპერაცია:

def missing_number_xor(nums: list) -> int:
    result = len(nums)
    for i, num in enumerate(nums):
        result ^= i ^ num
    return result

მუშაობს იმიტომ, რომ x ^ x = 0 — ყოველი წყვილი (ინდექსი, მნიშვნელობა), რომელიც ორივეჯერ გვხვდება, ერთმანეთს „აქრობს", და მხოლოდ დაუწყვილებელი (გამოტოვებული) რიცხვი რჩება. არც ჯამი გვჭირდება, არც overflow-ის რისკი.

05 — ამოცანა 4

Intersection of Two Arrays

ამოცანა: ორი მასივიდან დააბრუნეთ საერთო ელემენტები (თითოეული ერთხელ, თანმიმდევრობის მნიშვნელობის გარეშე).

🔗

პირდაპირი კავშირი ლექცია 2-თან: გახსოვთ ჩადგმული ციკლით დაწერილი intersect(), რომელიც O(n²)-ში მუშაობდა — და მისი გაუმჯობესებული, set-ზე დაფუძნებული ვერსია? ეს ზუსტად ის ამოცანაა, უბრალოდ ახლა ოფიციალურ LeetCode ფორმატში (LeetCode 349).

intersection.py
def intersection(nums1: list, nums2: list) -> list:
    return list(set(nums1) & set(nums2))

სირთულე: O(n + m) საშუალოდ — თითოეული მასივიდან set-ის აგება O(n)/O(m)-ია, თანაკვეთა საშუალოდ O(min(n, m))-ია.

🔍

შენიშვნა ორიგინალურობაზე: ეს ამოცანა კურსის მასალაში მხოლოდ სათაურის დონეზეა მოხსენიებული (სრული კოდი არ იყო მოცემული ორიგინალ სლაიდებში) — ამიტომ ზემოთ მოცემული ამოხსნა სრულად ჩვენს მიერაა დამატებული და გატესტილი, ლექცია 2-ის მასალის პირდაპირი გაგრძელების სახით.

07 — შემდგომი პრაქტიკა

დამატებითი LeetCode ვარიაციები

იგივე ოთხი პატერნის ბუნებრივი გაგრძელება — ოდნავ რთული ვარიაციები.

First Bad Version მარტივი

API isBadVersion(version) გეუბნებათ, ცუდია თუ არა კონკრეტული ვერსია — ყველა ვერსია ცუდი ვერსიის შემდეგაც ცუდია. იპოვეთ პირველი ცუდი ვერსია, API-ის გამოძახებების მინიმალური რაოდენობით (LeetCode 278).

def first_bad_version(n: int) -> int:
    left, right = 1, n
    while left < right:
        mid = left + (right - left) // 2
        if isBadVersion(mid):
            right = mid          # mid შეიძლება იყოს პასუხი — არ გამორიცხოთ
        else:
            left = mid + 1
    return left

იგივე „ჩასმის წერტილის" ლოგიკა, რაც Search Insert Position-ში — ვეძებთ არა კონკრეტულ მნიშვნელობას, არამედ საზღვარს ორ ზონას შორის (კარგი/ცუდი).

Intersection of Two Arrays II საშუალო

იგივე ამოცანა, მაგრამ ახლა დუბლიკატებიც უნდა აისახოს შედეგში იმდენჯერ, რამდენჯერაც ორივე მასივში მეორდება (LeetCode 350).

from collections import Counter

def intersect(nums1: list, nums2: list) -> list:
    counts1, counts2 = Counter(nums1), Counter(nums2)
    result = []
    for num, cnt in counts1.items():
        if num in counts2:
            result.extend([num] * min(cnt, counts2[num]))
    return result

set-ი აქ საკმარისი აღარაა, რადგან სიხშირის ინფორმაციას ვკარგავთ — Counter (hash map სიხშირეებით) ინარჩუნებს ორივე მასივში განმეორებათა რაოდენობას. სირთულე კვლავ O(n + m)-ია.

Find First and Last Position of Element in Sorted Array რთული

დალაგებულ მასივში, სადაც შესაძლოა დუბლიკატები იყოს, იპოვეთ target-ის პირველი და ბოლო პოზიცია O(log n) დროში (LeetCode 34).

def search_range(nums: list, target: int) -> list:
    def find_bound(is_first: bool) -> int:
        left, right = 0, len(nums) - 1
        result = -1
        while left <= right:
            mid = (left + right) // 2
            if nums[mid] == target:
                result = mid
                if is_first:
                    right = mid - 1   # ვაგრძელებთ მარცხნივ, უფრო ადრეულის საძებნად
                else:
                    left = mid + 1    # ვაგრძელებთ მარჯვნივ
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1
        return result

    return [find_bound(True), find_bound(False)]

იდეა: ორი ცალკე ორობითი ძებნა — ერთი „არ ჩერდება" პირველი დამთხვევისას, აგრძელებს მარცხნივ ყველაზე ადრეული პოზიციის საპოვნელად; მეორე იგივეს აკეთებს მარჯვნივ. სირთულე რჩება O(log n), თუნდაც ორჯერ ვასრულოთ ორობითი ძებნა — მუდმივი ჯერადობა ასიმპტოტურ კლასს არ ცვლის.
