01 — საბაზისო ცნება

რა არის რეკურსია

ტერმინი მომდინარეობს ლათინური სიტყვიდან recursio — „უკან დაბრუნება". რეკურსიული ფუნქცია ეწოდება ფუნქციას, რომელიც გადაწყვეტილებას პოულობს საკუთარი თავის გამოძახებით — ოღონდ ყოველ ჯერზე უფრო მარტივ, „შემცირებულ" ვერსიაზე.

ცენტრალური იდეა — დაყავი და იბატონე (divide and conquer): დიდი ამოცანა იშლება იმავე ტიპის, მაგრამ პატარა ქვეამოცანად, ვიდრე არ მივალთ იმდენად მარტივ შემთხვევამდე, რომ პასუხი პირდაპირ ცნობილია. ეს ზუსტად იმ პრინციპს გავს, რასაც მათემატიკური ინდუქცია იყენებს დამტკიცებისას — და ეს კავშირი შემთხვევითი არაა: ორივე მათემატიკური ინდუქციიდან იღებს სათავეს, და ლექციის ბოლოს ვნახავთ, როგორ ვამტკიცებთ რეკურსიული კოდის სისწორეს სწორედ ინდუქციით.

საბაზისო
შემთხვევა

ყოველი რგოლი — ერთი რეკურსიული გამოძახება, რომელიც საკუთარ თავს გადასცემს ოდნავ „შემცირებულ" ამოცანას

ყოველი რეკურსიული ფუნქცია აუცილებლად შედგება ორი ნაწილისგან — და ორივეს გამოტოვება (ან არასწორად ჩაწერა) ყველაზე ხშირი შეცდომაა დამწყები დეველოპერისთვის:

base case — საბაზისო შემთხვევა

ყველაზე მარტივი ვერსია ამოცანისა, რომლის პასუხიც პირდაპირ, რეკურსიის გარეშე ვიცით. სწორედ ეს აჩერებს გამოძახებების ჯაჭვს — მისი გარეშე ფუნქცია დაუსრულებლად გამოიძახებდა საკუთარ თავს, სანამ არ ამოეწურებოდა call stack-ი (RecursionError Python-ში).

recursive step — რეკურსიული ნაბიჯი

წესი, რომლითაც მიმდინარე ამოცანას ვამცირებთ და პასუხს ამ შემცირებულ ვერსიაზე ვანდობთ საკუთარი თავის გამოძახებას. აქ „ვენდობით", რომ ფუნქცია მართებულად იმუშავებს პატარა შემთხვევაზეც — ამ დაშვებას რეკურსიის რწმენის საფუძველს (recursive leap of faith) უწოდებენ.

💡

ტექნიკური ღრმა წერტილი: Python-ში თითოეული გამოძახება იკავებს ცალკე stack frame-ს მეხსიერებაში — საკუთარი ლოკალური ცვლადებით. ამიტომ, თუნდაც ცვლადს ერთი და იგივე სახელი ჰქონდეს ყველა გამოძახებაში (მაგ. n), თითოეული ასლი დამოუკიდებელია. ნაკადის კონტროლი წინა (მშობელ) სკოუპს უბრუნდება მხოლოდ მას შემდეგ, რაც მიმდინარე გამოძახება მნიშვნელობას დააბრუნებს.

02 — პირველი მაგალითი

ორი რიცხვის გადამრავლება

ნამრავლი a × b შეიძლება წარმოვადგინოთ, როგორც a-ს საკუთარ თავთან დაჯამება b-ჯერ. ეს გვაძლევს ორ სრულიად განსხვავებულ, მაგრამ თანაბრად სწორ გზას ამოცანის გადასაჭრელად.

იტერაციული ამოხსნა
multiply_iter.py
def multiply_iterative(a: int, b: int) -> int:
    """a * b — მარტივი მარყუჟით."""
    result = 0
    for _ in range(b):
        result += a
    return result
რეკურსიული ამოხსნა
multiply_recursive.py
def multiply_recursive(a: int, b: int) -> int:
    """a * b = a + a * (b - 1)."""
    if b == 0:               # საბაზისო შემთხვევა
        return 0
    return a + multiply_recursive(a, b - 1)
🔍

შესწორება ორიგინალი მასალიდან: ლექციის საწყის ვერსიაში საბაზისო შემთხვევად აღებული იყო b == 1. ეს მუშაობს, სანამ b ≥ 1-ია, მაგრამ multiply_recursive(a, 0)-ზე გამოძახება არასდროს „დაეჯახება" საბაზისო შემთხვევას — b გახდება -1, -2, -3… და ფუნქცია უსასრულოდ გააგრძელებს გამოძახებას, სანამ არ მიიღებთ RecursionError-ს. მათემატიკურად სწორი საბაზისო შემთხვევაა b == 0 → 0, რაც ასევე ემთხვევა ცნობილ ფაქტს: ნებისმიერი რიცხვი ნულზე გამრავლებული — ნულია.

მახასიათებელიიტერაციულირეკურსიული
დროითი სირთულეO(b)O(b)
მეხსიერების სირთულეO(1)O(b) — call stack

ორივე ვერსია ერთნაირად „ნელია" დროში, მაგრამ რეკურსიული ვერსია დამატებით მეხსიერებას ხარჯავს — თითოეული აქტიური გამოძახება call stack-ზე ჩერდება, სანამ შიდა გამოძახება არ დაბრუნდება.

03 — call stack ვიზუალურად

ფაქტორიალი და გამოძახებების სტეკი

n! = n × (n−1) × (n−2) × … × 1. საბაზისო შემთხვევა: 0! = 1. რეკურსიული ნაბიჯი: n! = n × (n−1)!

factorial.py
def factorial(n: int) -> int:
    """n! გამოთვლა რეკურსიით."""
    if n < 0:
        raise ValueError("n უნდა იყოს არაუარყოფითი")
    if n <= 1:                      # საბაზისო შემთხვევა: 0! = 1! = 1
        return 1
    return n * factorial(n - 1)     # რეკურსიული ნაბიჯი
🔍

შესწორება ორიგინალი მასალიდან: საწყისი კოდი საბაზისო შემთხვევად იღებდა მხოლოდ n == 1-ს, რაც არასწორ პასუხს (ან უსასრულო რეკურსიას) გამოიღებდა n = 0-ზე — მაშინ როცა მათემატიკურად 0! = 1. თანამედროვე, სუფთა კოდის სტანდარტი ასევე მოითხოვს უარყოფითი შემოტანის დაცვას (ValueError) — ეს არის ე.წ. defensive programming, ინდუსტრიაში მიღებული პრაქტიკა API-ების დასაწერად.

სტეკი იზრდება ქვემოდან ზემოთ — ბოლოს დამატებული ჩარჩო ყოველთვის ზემოთაა. საბაზისო შემთხვევა (ოქროსფერი) აჩერებს ზრდას, შემდეგ სტეკი „იშლება" უკან, ისე რომ თითოეული გამოძახება ითვლის საკუთარ ნამრავლს.

⚠️

რეალური შეზღუდვა Python-ში: ენას არ გააჩნია tail call optimization (განსხვავებით, მაგალითად, Scheme-სგან) — ანუ ყოველი რეკურსიული გამოძახება ნამდვილად იკავებს მეხსიერებას, სანამ არ დაბრუნდება. ნაგულისხმევი ლიმიტია დაახლოებით 1000 ჩაშენებული გამოძახება (sys.getrecursionlimit()), რის შემდეგაც პროგრამა შეწყვეტს მუშაობას RecursionError-ით. ეს ერთ-ერთი მთავარი მიზეზია, რატომ ამჯობინებენ დიდ სისტემებში (მაგ. Google-ის ინფრასტრუქტურაში) ღრმა რეკურსიის ნაცვლად იტერაციულ ან ე.წ. trampoline ტექნიკებს.

04 — არჩევანი

იტერაცია vs რეკურსია

არც ერთი მიდგომა არ არის „უნივერსალურად სჯობს" — არჩევანი დამოკიდებულია ამოცანის ბუნებასა და გუნდის პრიორიტეტებზე.

იტერაციარეკურსია
ჩვეულებრივ უფრო სწრაფი და მეხსიერებაზე ეკონომიური — არ ტოვებს stack frame-ებს. ხშირად გაცილებით უფრო მარტივი და ინტუიციური იმ ამოცანებისთვის, რომლებსაც ბუნებრივად აქვთ „ხის" ან „თვითმსგავსი" სტრუქტურა (ხეები, ფრაქტალები, ჩაბუდებული მონაცემები).
საჭიროებს ცვლადების ხელით მართვას (counter, accumulator). კოდი ხშირად პირდაპირ ასახავს მათემატიკურ განსაზღვრებას — ნაკლები ბაგის რისკი სწორად დაწერისას.
არ არსებობს stack overflow-ის რისკი. ღრმა რეკურსიაზე შესაძლებელია RecursionError — განსაკუთრებით საშიშია დამუშავებულ, არაკონტროლირებად შემოტანაზე (მაგ. ღრმად ჩადგმული JSON).
🏭

Tech Industry Insight: ფუნქციური ენები (Haskell, Scheme, Erlang) ეყრდნობა თითქმის მხოლოდ რეკურსიას მარყუჟების ნაცვლად და საკომპილაციო დონეზე გარდაქმნის მას იტერაციად (tail call optimization). Python ამას ავტომატურად არ აკეთებს — ამიტომ production კოდში ხშირად ხედავთ ჰიბრიდულ მიდგომას: ალგორითმი კონცეპტუალურად რეკურსიულადაა ჩაფიქრებული (მარტივი მტკიცების გამო), მაგრამ იმპლემენტაცია — იტერაციული ან memoized, წარმადობისთვის.

05 — რატომ „ვენდობით" რეკურსიას

მათემატიკური ინდუქცია

საიდან ვიცით, რომ ჩვენი რეკურსიული ფუნქცია საერთოდ იმუშავებს? პასუხი — იმავე ლოგიკიდან, რასაც მათემატიკური ინდუქცია იყენებს ნებისმიერი ნატურალური რიცხვისთვის დებულების დასამტკიცებლად:

  1. საბაზისო შემთხვევა (base): ვამტკიცებთ დებულებას უმცირესი n-ისთვის.
  2. ინდუქციური დაშვება (hypothesis): ვუშვებთ, რომ დებულება ჭეშმარიტია n-ისთვის.
  3. ინდუქციური ნაბიჯი (step): ვაჩვენებთ, რომ დაშვებიდან გამომდინარეობს დებულების ჭეშმარიტება n + 1-ისთვის.

მაგალითი: დავამტკიცოთ, რომ 0 + 1 + 2 + … + n = n(n+1)/2.

ბაზისი: n=0-სთვის ორივე მხარე ნულის ტოლია. ✓
დაშვება: ვთვლით, რომ 0+1+…+k = k(k+1)/2.
ნაბიჯი: 0+1+…+k+(k+1) = k(k+1)/2 + (k+1) = (k+1)(k+2)/2 — ზუსტად ის ფორმულა, რასაც ვამტკიცებდით n = k+1-ისთვის. ∎

🧩

კავშირი კოდთან: ზუსტად ასევე ვამტკიცებთ, რომ multiply_recursive(a, b) სწორად მუშაობს ნებისმიერ b-ზე: (1) ვამტკიცებთ b = 0-ზე — უბრალოდ აბრუნებს 0-ს, სწორია; (2) ვუშვებთ, რომ სწორად მუშაობს b-ზე ნაკლებ ყველა მნიშვნელობაზე („recursive leap of faith"); (3) ვაჩვენებთ, რომ a + multiply_recursive(a, b-1) სწორად გამოთვლის b-ს შემთხვევასაც. ეს არის ის მიზეზი, რის გამოც არასოდეს გვჭირდება იმის „გამორბენა თავში", თუ როგორ იმუშავებს ფუნქცია სამ-ოთხ დონეზე ღრმად — საკმარისია დავრწმუნდეთ საბაზისო შემთხვევასა და ერთ ნაბიჯში.

06 — კლასიკური ამოცანა

ჰანოის კოშკები

ლეგენდის მიხედვით, ბერები ცდილობენ n ფირფიტის გადატანას ერთი ღერძიდან მეორეზე დამხმარე ღერძის გამოყენებით — დიდი ფირფიტა არასდროს არ შეიძლება აღმოჩნდეს პატარაზე ზემოთ, და ერთ ჯერზე მხოლოდ ერთი ფირფიტის გადატანაა შესაძლებელი.

რეკურსიული იდეა კრისტალურად მარტივია: რომ გადავიტანოთ n ფირფიტა A-დან C-ზე (B-ს დახმარებით) —

  1. გადავიტანოთ ზედა n−1 ფირფიტა A-დან B-ზე (C-ს დახმარებით);
  2. გადავიტანოთ ყველაზე დიდი ფირფიტა A-დან C-ზე;
  3. გადავიტანოთ n−1 ფირფიტა B-დან C-ზე (A-ს დახმარებით).
hanoi.py
def hanoi(n: int, source: str, target: str, auxiliary: str) -> list[str]:
    """აბრუნებს n-დისკიანი ამოცანის ამოხსნის ნაბიჯების სიას."""
    if n == 0:
        return []
    return (
        hanoi(n - 1, source, auxiliary, target)
        + [f"{source} → {target}"]
        + hanoi(n - 1, auxiliary, target, source)
    )

ფიბონაჩის რიცხვები

ფიბონაჩის მიმდევრობაში ყოველი წევრი წინა ორის ჯამია: 0, 1, 1, 2, 3, 5, 8, 13, 21… ბუნებრივი განმარტება პირდაპირ გარდაიქმნება რეკურსიულ კოდად:

def fib(n: int) -> int:
    """F(0)=0, F(1)=1, F(n)=F(n-1)+F(n-2)."""
    if n in (0, 1):          # ორი საბაზისო შემთხვევა
        return n
    return fib(n - 1) + fib(n - 2)

ამ ვერსიას ორი საბაზისო შემთხვევა აქვს — და აქ იმალება პრობლემა: fib(n-1) და fib(n-2) ორივე ცალ-ცალკე იძახებენ იმავე ქვე-მნიშვნელობებს თავიდან. ქვემოთ ჩანს ეს გამეორება fib(5)-ის გამოძახებების ხედან:

from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n: int) -> int:
    if n in (0, 1):
        return n
    return fib(n - 1) + fib(n - 2)

def is_palindrome(text: str) -> bool:
    """ამოწმებს, არის თუ არა სტრიქონი პალინდრომი (მხოლოდ ასოებზე დაყრდნობით)."""
    cleaned = "".join(ch.lower() for ch in text if ch.isalpha())

    def check(s: str) -> bool:
        if len(s) <= 1:              # საბაზისო შემთხვევა
            return True
        return s[0] == s[-1] and check(s[1:-1])   # რეკურსიული ნაბიჯი

    return check(cleaned)

საბაზისო სავარჯიშოები

ეს ექვსი ამოცანა პირდაპირ თვითონ ლექციიდანაა აღებული — გახსენით ამოხსნა შემოწმებისთვის.

1. დაწერეთ რეკურსიული ფუნქცია, რომელიც სტრიქონს შეაბრუნებს 
def reverse(s: str) -> str:
    if len(s) <= 1:
        return s
    return reverse(s[1:]) + s[0]

საბაზისო შემთხვევა — ცარიელი ან ერთსიმბოლოიანი სტრიქონი. თითოეულ ნაბიჯზე პირველ სიმბოლოს ბოლოში ვსვამთ.

2. დაწერეთ რეკურსიული ფუნქცია, რომელიც დათვლის n-ის m ხარისხს 
def power(n: int, m: int) -> int:
    if m == 0:
        return 1
    return n * power(n, m - 1)

O(m) სირთულის მარტივი ვერსია. ქვემოთ, "საშუალო" სავარჯიშოებში ნახავთ, როგორ ავაშენოთ O(log m) ვერსია.

3. დაწერეთ რეკურსიული ფუნქცია, რომელიც პოულობს სიის მაქსიმალურ ელემენტს 
def find_max(nums: list[int]) -> int:
    if len(nums) == 1:
        return nums[0]
    rest_max = find_max(nums[1:])
    return nums[0] if nums[0] > rest_max else rest_max
4. დაწერეთ რეკურსიული ფუნქცია, რომელიც იპოვის რიცხვის ციფრების ჯამს 
def digit_sum(n: int) -> int:
    n = abs(n)
    if n < 10:
        return n
    return n % 10 + digit_sum(n // 10)
5. დაწერეთ რეკურსიული ფუნქცია, რომელიც მოძებნის კონკრეტულ ელემენტს სიაში 
def contains(nums: list[int], target: int) -> bool:
    if not nums:
        return False
    if nums[0] == target:

def is_sorted(nums: list[int]) -> bool:

Power of Two მარტივი

დაადგინეთ, არის თუ არა მთელი დადებითი რიცხვი 2-ის ხარისხი (LeetCode 231).

def is_power_of_two(n: int) -> bool:
    if n <= 0:
        return False
    if n == 1:
        return True
    if n % 2 != 0:
        return False
    return is_power_of_two(n // 2)

საბაზისო შემთხვევები ორია: n ≤ 0 (ცრუ) და n == 1 (ჭეშმარიტი, ვინაიდან 2⁰=1). დროითი სირთულე — O(log n), რადგან ყოველ ნაბიჯზე n ორად იყოფა.

Subsets (ყველა ქვესიმრავლე) საშუალო

დაბრუნეთ სიის ყველა შესაძლო ქვესიმრავლე — Power Set (LeetCode 78). ეს ზუსტად ის ცნებაა, რომელსაც სილაბუსის მე-3 კვირის თემა ეხება.

def subsets(nums: list[int]) -> list[list[int]]:
    if not nums:
        return [[]]
    first, rest = nums[0], nums[1:]
    without_first = subsets(rest)
    with_first = [[first] + s for s in without_first]
    return without_first + with_first

ყოველი ელემენტისთვის ორი შესაძლებლობაა — ან შედის ქვესიმრავლეში, ან არა. საბაზისო შემთხვევა — ცარიელი სია, რომლის ერთადერთი ქვესიმრავლე თავად ცარიელი სიაა. სირთულე — O(2ⁿ), რადგან თავად პასუხი 2ⁿ ქვესიმრავლისგან შედგება.

Pow(x, n) — სწრაფი ხარისხში აყვანა საშუალო

გამოთვალეთ xⁿ ეფექტურად (LeetCode 50) — ე.წ. fast exponentiation, divide-and-conquer-ის კლასიკური მაგალითი.

def my_pow(x: float, n: int) -> float:
    if n < 0:
        return 1 / my_pow(x, -n)
    if n == 0:
        return 1.0
    half = my_pow(x, n // 2)
    return half * half if n % 2 == 0 else half * half * x

ნაცვლად იმისა, რომ n-ჯერ გავამრავლოთ x (O(n), სავარჯიშო #2-ის მსგავსად), ვამცირებთ ამოცანას განახევრებით — xⁿ = (x^(n/2))². სირთულე მცირდება O(n)-დან O(log n)-მდე. ეს ზუსტად ის ტექნიკაა, რასაც კრიპტოგრაფიული ბიბლიოთეკები იყენებენ დიდი რიცხვების სწრაფად ხარისხში ასაყვანად.

N-Queens რთული

დაასახლეთ n ლომი n×n ჭადრაკის დაფაზე ისე, რომ არც ერთი ორი ლომი ერთმანეთს არ დაემუქროს (LeetCode 51) — backtracking-ის ეტალონური ამოცანა.

def solve_n_queens(n: int) -> int:
    def is_safe(cols: list[int], row: int, col: int) -> bool:
        for r, c in enumerate(cols):
            if c == col or abs(c - col) == row - r:
                return False
        return True

    def backtrack(cols: list[int]) -> int:
        row = len(cols)
        if row == n:
            return 1
        count = 0
        for col in range(n):
            if is_safe(cols, row, col):
                count += backtrack(cols + [col])
        return count

    return backtrack([])

backtrack სტრიქონის მაგივრად სვეტების სიას ავსებს რიგრიგობით — რიგში ერთი ლომი. თუ პოზიცია არაა უსაფრთხო, უბრალოდ არ ვაგრძელებთ იმ ტოტს („ვბრუნდებით უკან"). უარეს შემთხვევაში სირთულეა O(n!) — მაგრამ is_safe-ის შემოწმება ბევრ ტოტს ადრეულ ეტაპზევე ჭრის.
