01 — ახალი კატეგორია

რა არის ორობითი ხე

ბმული სია (ლექცია 7-9) წრფივი სტრუქტურაა — ყოველ კვანძს ერთი „შემდეგი" ჰყავს. ორობითი ხე ამის საპირისპიროა: იერარქიული, არაწრფივი სტრუქტურა, სადაც თითოეულ კვანძს შეიძლება ჰყავდეს მაქსიმუმ ორი „შვილი" — მარცხენა და მარჯვენა.

ხის ყველაზე ზედა კვანძს — root (ფესვი) — ეწოდება, და მისგან იწყება ყველა გზა ხის დანარჩენ ნაწილამდე. კვანძები, რომლებსაც შვილი არ ჰყავთ, ფოთლებია (leaves).

💡

რატომ „არაწრფივი": ბმულ სიაში ერთადერთი გზაა წინ სვლა. ხეში კი, ყოველ კვანძზე, გზა იშლება — შეგვიძლია წავიდეთ მარცხნივ ან მარჯვნივ. ეს განშტოება ხდის შესაძლებელს იმას, რასაც ხეები ისე კარგად აკეთებენ — იერარქიების, გადაწყვეტილებების და დალაგებული მონაცემების ბუნებრივად წარმოდგენას.

02 — ლექსიკონი

ძირითადი ტერმინოლოგია

root (ფესვი)

ხის ყველაზე ზედა კვანძი. მშობელი არ ჰყავს — ის არის ამოსავალი წერტილი ყველა შემოვლისთვის.

parent / child

კვანძი, რომელსაც აქვს ერთი ან ორი შვილობილი კვანძი — მშობელია; შვილობილი კვანძები მისი შვილები არიან.

leaf (ფოთოლი)

კვანძი, რომელსაც არცერთი შვილი არ ჰყავს — ორივე left და right არის None.

internal node (შიდა კვანძი)

კვანძი მინიმუმ ერთი შვილით — ეს არის ყველა კვანძი, გარდა root-ისა და ფოთლებისა.

depth (სიღრმე)

წიბოების რაოდენობა კონკრეტული კვანძიდან root-მდე. Root-ის სიღრმე — 0.

height (სიმაღლე)

კვანძების რაოდენობა ყველაზე ღრმა ფოთლიდან root-მდე — გვხვდება Big-O ანალიზში ხშირად, როგორც h.

03 — სამშენებლო ბლოკი

კვანძის სტრუქტურა

ბმული სიის Node-ს (ერთი next-ით) ემატება მეორე მაჩვენებელი — left და right ერთი next-ის ნაცვლად:

binary_tree.py
class Node:
    def __init__(self, d):
        self.data = d
        self.left = None
        self.right = None

# ხელით ავაგოთ პატარა ხე:
#         1
#       /   \
#      2     3
#       \
#        4
first_node = Node(2)
second_node = Node(3)
third_node = Node(4)
root = Node(1)

root.left = first_node
root.right = second_node
first_node.right = third_node

ორობითი ხის აგება, ისევე როგორც ბმული სიის, ხდება მხოლოდ მაჩვენებლების დაკავშირებით — არა რაიმე ცალკე „კონტეინერის" კლასით.

04 — სამი გზა

ორობითი ხის შემოვლის ალგორითმები

„შემოვლა" (traversal) — ხის ყველა კვანძის სისტემატური მონახულების პროცესია. სამივე ძირითადი ვარიანტი ეყრდნობა ერთსა და იმავე რეკურსიულ ჩონჩხს — განსხვავება მხოლოდ იმაშია, როდის ვკითხულობთ მიმდინარე კვანძის მონაცემს, მარცხენა და მარჯვენა ქვეხეების შემოვლასთან შედარებით.

მაგალითისთვის გამოვიყენებთ ერთსა და იმავე პატარა ხეს მთელი ამ სექციის განმავლობაში:

1 / \ 2 3 / \ \ 4 5 6
05 — Inorder

Inorder Traversal

თანმიმდევრობა: მარცხენა → root → მარჯვენა

def print_inorder(node: "Node") -> None:
    if node is None:
        return
    print_inorder(node.left)          # 1. მარცხენა ქვეხე
    print(node.data, end=' ')         # 2. root
    print_inorder(node.right)         # 3. მარჯვენა ქვეხე

ჩვენს მაგალითზე: შემოვლა იწყება 1-დან, ეშვება 2-ში, შემდეგ 4-ში — 4-ს არც მარცხენა და არც მარჯვენა ქვეხე არ აქვს, ამიტომ ვკითხულობთ მას პირველად. ვბრუნდებით 2-ში (მარცხენა ქვეხე დასრულებულია) — ვკითხულობთ 2-ს, შემდეგ ვშედივართ მის მარჯვენა ქვეხეში (5), ვკითხულობთ 5-ს. ვბრუნდებით 1-ში, ვკითხულობთ მას, შემდეგ ვშედივართ მარჯვენა ქვეხეში (3 → 6).

დროითი სირთულემეხსიერებითი სირთულე
O(n)O(h) — რეკურსიული call stack
🎯

ყველაზე მნიშვნელოვანი გამოყენება: ორობითი ძებნის ხეზე (Binary Search Tree — ლექცია 13-ში), Inorder Traversal ყოველთვის აბრუნებს მონაცემებს ზრდადობით დალაგებული თანმიმდევრობით — ეს არაა დამთხვევა, არამედ BST-ის განმსაზღვრელი თვისება.

06 — Preorder

Preorder Traversal

თანმიმდევრობა: root → მარცხენა → მარჯვენა

def print_preorder(node: "Node") -> None:
    if node is None:
        return
    print(node.data, end=' ')         # 1. root
    print_preorder(node.left)         # 2. მარცხენა ქვეხე
    print_preorder(node.right)        # 3. მარჯვენა ქვეხე

ჩვენს მაგალითზე: ვკითხულობთ 1-ს დაუყოვნებლივ, შემდეგ ვშედივართ მარცხენა ქვეხეში — ვკითხულობთ 2-ს, ვშედივართ მის მარცხენაში — ვკითხულობთ 4-ს. ვბრუნდებით და ვკითხულობთ 5-ს. ვბრუნდებით root-ში, ვშედივართ მარჯვენა ქვეხეში — ვკითხულობთ 3-ს, შემდეგ 6-ს. შედეგი: 1, 2, 4, 5, 3, 6.

დროითი სირთულემეხსიერებითი სირთულე
O(n)O(1) დამატებითი — ან O(h), თუ call stack-საც ჩავთვლით
🏗️

გამოყენება: Preorder საუკეთესოა ხის ხელახლა აგებისთვის ან კლონირებისთვის — რადგან root ყოველთვის პირველია, თანმიმდევრობის წაკითხვისას პირველ ელემენტს ახალი ქვეხის root-ად ავიღებთ ცალსახად.

07 — Postorder

Postorder Traversal

თანმიმდევრობა: მარცხენა → მარჯვენა → root

def print_postorder(node: "Node") -> None:
    if node is None:
        return
    print_postorder(node.left)        # 1. მარცხენა ქვეხე
    print_postorder(node.right)       # 2. მარჯვენა ქვეხე
    print(node.data, end=' ')         # 3. root
🔍

შესწორება ორიგინალ მასალასთან შედარებით: საწყისი კოდი წერდა if node == None: — მაშინ როცა იმავე ლექციის Inorder და Preorder ფუნქციები სწორად იყენებდნენ is None-ს. == None ხშირად „მუშაობს", რადგან უმეტეს კლასებს საკუთარი __eq__ არ აქვთ განსაზღვრული — მაგრამ PEP 8 (Python-ის ოფიციალური სტილის სახელმძღვანელო) ცალსახად მოითხოვს is None-ს None-თან შედარებისას: ის ყოველთვის სწორია, მიუხედავად იმისა, აქვს თუ არა კლასს მორგებული __eq__ (მაგ. NumPy მასივებს, სადაც == None მთლიანად სხვა რამეს აკეთებს). სამივე ფუნქცია ახლა თანმიმდევრულია.

ჩვენს მაგალითზე: ჯერ სრულად ვშემოივლით მარცხენა ქვეხეს (4, შემდეგ 5, შემდეგ 2), მერე მარჯვენას (6, შემდეგ 3), და ბოლოს — root-ს (1). შედეგი: 4, 5, 2, 6, 3, 1.

დროითი სირთულემეხსიერებითი სირთულე
O(n)O(1) დამატებითი — ან O(h) call stack-ით
🗑️

გამოყენება: Postorder საუკეთესოა კვანძების წაშლისთვის — ლოგიკურია, რომ ჯერ ვშლით შვილებს, მერე მშობელს, არა პირიქით (წინააღმდეგ შემთხვევაში დაკარგავდით მითითებას შვილებზე).

08 — სცადეთ თავად

შემოვლის ინტერაქტიული ვიზუალიზაცია

აირჩიეთ შემოვლის ტიპი და თვალი ადევნეთ, როგორ მოძრაობს რეკურსია ხეზე — ლურჯი, წყვეტილი ჩარჩო ნიშნავს „ვსტუმრობთ ამ კვანძს" (რეკურსიაში შესვლა), ხოლო ოქროსფერი შევსება — „ვკითხულობთ მონაცემს" (გამოტანა შედეგში).

სავარჯიშო — უფრო დიდი ხე

პროგრამის კოდი კომპილაციისას გარდაიქმნება Abstract Syntax Tree-ად (AST) — კოდის ანალიზი, ოპტიმიზაცია და გენერაცია ყველა ეყრდნობა ხის სხვადასხვა ტიპის შემოვლას.

12 — დამატებითი ამოცანები

გაფართოებული პრაქტიკა

დღეს ნასწავლი შემოვლის ტექნიკების ბუნებრივი გაგრძელება — „ხის ამოცანებს" კურსში მომდევნო ლექციაზე უფრო ღრმად შევეხებით, აქ კი ვამყარებთ თავად შემოვლის კონცეფციას.

Binary Tree Level Order Traversal მარტივი

დღეს ნასწავლი სამივე ალგორითმი — Inorder, Preorder, Postorder — სიღრმეზე დაფუძნებულია (depth-first): ჯერ ღრმად ჩავდივართ, მერე ვბრუნდებით. არსებობს მეოთხე, სრულიად განსხვავებული მიდგომაც — სიგანეზე დაფუძნებული (breadth-first): ჯერ ყველა კვანძი ერთ დონეზე, მერე შემდეგ დონეზე. დააბრუნეთ ხის კვანძების მნიშვნელობები დონეების მიხედვით (LeetCode 102).

from collections import deque

def level_order(root: "Node") -> list:
    if root is None:
        return []
    result = []
    queue = deque([root])
    while queue:
        level = []
        for _ in range(len(queue)):
            node = queue.popleft()
            level.append(node.data)
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
        result.append(level)
    return result

საკვანძო განსხვავება: Inorder/Preorder/Postorder რეკურსიას (და შიგნით — call stack-ს, ანუ stack-ის ლოგიკას) იყენებენ. Level Order კი queue-ს (რიგს) იყენებს — პირველი შემოსული კვანძი, პირველივე მუშავდება. სირთულე: O(n) დროში, O(n) სივრცეში (უარეს შემთხვევაში ბოლო დონეს შეუძლია შეიცავდეს n/2-მდე კვანძი).

Validate Binary Search Tree საშუალო

დაადგინეთ, აკმაყოფილებს თუ არა მოცემული ორობითი ხე BST-ის თვისებას — თითოეული კვანძისთვის, მისი მარცხენა ქვეხის ყველა მნიშვნელობა მასზე ნაკლები უნდა იყოს, მარჯვენას კი — მეტი (LeetCode 98).

def is_valid_bst(root: "Node") -> bool:
    def validate(node, low, high) -> bool:
        if node is None:
            return True
        if not (low < node.data < high):
            return False
        return (validate(node.left, low, node.data) and
                validate(node.right, node.data, high))
    return validate(root, float('-inf'), float('inf'))

ხშირი შეცდომა, რომლისგანაც ეს ამონახსნი იცავს: არასაკმარისია მხოლოდ პირდაპირი შვილების შემოწმება (node.left.data < node.data) — BST-ის პირობა ვრცელდება მთელ ქვეხეზე, არა მხოლოდ უშუალო შვილებზე. ამიტომ თითოეულ რეკურსიულ გამოძახებაში „ვავიწროებთ" დასაშვებ დიაპაზონს (low, high) — ეს პირდაპირ უკავშირდება დღეს ნასწავლ Inorder-ის თვისებას (BST-ის Inorder = დალაგებული თანმიმდევრობა).

Construct Binary Tree from Preorder and Inorder Traversal რთული

მოცემულია ერთი და იმავე ხის Preorder და Inorder შემოვლის შედეგები — აღადგინეთ თავად ხე (LeetCode 105).

def build_tree(preorder: list, inorder: list) -> "Node":
    if not preorder or not inorder:
        return None

    root_val = preorder[0]          # Preorder-ის პირველი ელემენტი — ყოველთვის root
    root = Node(root_val)

    mid = inorder.index(root_val)   # root-ის პოზიცია Inorder-ში ყოფს ხეს ორად

    root.left = build_tree(preorder[1:mid + 1], inorder[:mid])
    root.right = build_tree(preorder[mid + 1:], inorder[mid + 1:])
    return root

რატომ საკმარისია ეს ორი შემოვლა (და არა, მაგალითად, Preorder მარტო): Preorder-ის პირველი ელემენტი ყოველთვის root-ია — მაგრამ მარტო ამით ვერ ვიტყვით, სად მთავრდება მარცხენა ქვეხე და სად იწყება მარჯვენა. Inorder კი, სადაც root ყოველთვის ქვეხეებს შორის დგას (დღეს ნასწავლი პირველი ფაქტი!), ზუსტად ამ ინფორმაციას გვაძლევს — ყველაფერი root-მდე მარცხენა ქვეხეა, ყველაფერი მის შემდეგ — მარჯვენა. ეს ამოცანა პირდაპირ გამოხატავს, რატომ აქვს თითოეულ შემოვლის ტიპს საკუთარი, უნიკალური „ხელწერა".
