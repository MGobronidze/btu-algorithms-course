Quick Sort

არა გაერთიანება — გადანაწილება. ალგორითმი, რომელიც არჩეული „წამყვანის" (pivot) გარშემო გადააწყობს მასივს — და საშუალოდ ყველაზე სწრაფია პრაქტიკაში.

pivotpartitionO(n log n) საშუალოდO(n²) უარესში
01 — მესამე მიდგომა

დალაგების მესამე ფილოსოფია

გავიხსენოთ ლექცია 4: Insertion Sort მარტივია, მაგრამ O(n²); Merge Sort გარანტირებულად O(n log n), მაგრამ O(n) დამატებით მეხსიერებას ითხოვს. Quick Sort — მესამე გზა: divide-and-conquer, Merge Sort-ის მსგავსად, მაგრამ „ჭკვიანურად" იყოფა და იბატონებს ისე, რომ დამატებითი მასივი აღარ სჭირდება.

📜

ისტორიული ცნობა: Quick Sort შექმნა ბრიტანელმა კომპიუტერულმა მეცნიერმა ტონი ჰოარმა 1959 წელს (გამოქვეყნდა 1961-ში). დღემდე ერთ-ერთი ყველაზე ფართოდ გამოყენებული დალაგების ალგორითმია — ხშირად ოდნავ უფრო სწრაფიც კი Merge Sort-სა და Heap Sort-ზე, განსაკუთრებით შემთხვევითი, დიდი მოცულობის მონაცემისთვის.

02 — მექანიზმი

როგორ მუშაობს Quick Sort

  1. Pivot-ის არჩევა: მასივიდან ვირჩევთ „წამყვან" ელემენტს — Pivot.
  2. გაყოფა (partition): მასივს გადავაწყობთ ისე, რომ Pivot-ზე მცირე ელემენტები აღმოჩნდნენ მის მარცხნივ, დიდები — მარჯვნივ. ამის შემდეგ Pivot უკვე თავის საბოლოო, სწორ პოზიციაზეა.
  3. რეკურსიული გამოძახება: იგივე პროცესი მეორდება ორივე ქვემასივზე — Pivot-ის მარცხნივ და მარჯვნივ.
  4. საბაზისო შემთხვევა: ერთ ან ნულ ელემენტიანი ქვემასივი უკვე დალაგებულია.
quick_sort.py
def quick_sort(arr: list, low: int, high: int) -> None:
    if low < high:
        pi = partition(arr, low, high)   # Pivot ხვდება სწორ ადგილას
        quick_sort(arr, low, pi - 1)     # მარცხენა ნაწილი
        quick_sort(arr, pi + 1, high)    # მარჯვენა ნაწილი

ცენტრალური განსხვავება Merge Sort-თან: Merge Sort ყოფს ბრმად (ყოველთვის ზუსტად შუაზე) და მთელი „ჭკუა" merge-ის ეტაპშია. Quick Sort პირიქით — ჭკვიანურად ყოფს (partition აწყობს ელემენტებს სწორ მხარეს) და ბოლოს აღარაფერი „გასაერთიანებელი" აღარ რჩება.

03 — კრიტიკული გადაწყვეტილება

Pivot-ის არჩევა

მთელი ალგორითმის წარმადობა დამოკიდებულია იმაზე, თუ რამდენად „კარგად" ყოფს Pivot მასივს. სამი ძირითადი სტრატეგია:

სტრატეგიადახასიათებარისკი
პირველი/ბოლო ელემენტიუმარტივესი იმპლემენტაციაუკვე დალაგებულ (ან უკუდალაგებულ) მასივზე — გარანტირებული O(n²)
შემთხვევითი ელემენტისაუკეთესო პრაქტიკული არჩევანიარ არსებობს კონკრეტული შემავალი პატერნი, რომელიც სისტემატურად უარეს შემთხვევას გამოიწვევდა
მედიანათეორიულად იდეალური — ყოველთვის ზუსტად შუაზე ყოფსმედიანის პოვნა თავად მოითხოვს დამატებით სამუშაოს — პრაქტიკაში იშვიათად ღირს
⚠️

რატომ არის „ბოლო ელემენტი" სახიფათო: თუ მასივი უკვე დალაგებულია და ყოველთვის ბოლო ელემენტს ვირჩევთ Pivot-ად, თითოეული partition მასივს ყოფს 1 და n−1 ზომის ნაწილებად — ყველაზე არაბალანსებული გაყოფა შესაძლო ვარიანტებს შორის. ქვემოთ, ინტერაქტიულ ექსპერიმენტში, ამას ზუსტი რიცხვებით ვნახავთ.

04 — გული

Partition ალგორითმი — Lomuto-ს სქემა

Partition — Quick Sort-ის ცენტრალური ნაბიჯია. სამი ძირითადი სქემა არსებობს (ყველა O(n) დროში), აქ ვიწყებთ ყველაზე გასაგები — Lomuto-ს სქემით: ვირჩევთ ბოლო ელემენტს Pivot-ად და ვინახავთ ინდექსს i — „უკვე დანახული, Pivot-ზე მცირე ელემენტების ზონის" ბოლოს.

lomuto_partition.py
def partition(arr: list, low: int, high: int) -> int:
    pivot = arr[high]
    i = low - 1                    # "მცირეთა ზონის" ბოლო ინდექსი
    for j in range(low, high):
        if arr[j] <= pivot:
            i += 1
            arr[i], arr[j] = arr[j], arr[i]
    arr[i + 1], arr[high] = arr[high], arr[i + 1]   # Pivot სწორ ადგილას
    return i + 1                   # Pivot-ის საბოლოო ინდექსი

ოქროსფერი — Pivot (ბოლო ელემენტი). ლურჯისებრი — მიმდინარე შედარება (j). მწვანე — Pivot-ის საბოლოო, დალაგებული პოზიცია.

05 — სირთულის ანალიზი

როდის სწრაფია, როდის ნელი

შემთხვევარა ხდებასირთულე
საუკეთესოPivot ყოველთვის მასივს თანაბარ ნაწილებად ყოფს — log n დონე, თითოეულზე O(n) სამუშაოO(n log n)
საშუალოPivot არც ზედმეტად მცირეა, არც ზედმეტად დიდი — რეკურსიის სიღრმე კვლავ საშუალოდ O(log n)-იაO(n log n)
უარესიPivot ყოველთვის უმცირესი/უდიდესია (მაგ. დალაგებულ მასივზე ბოლო ელემენტი) — n დონე რეკურსიაშიO(n²)
∑

საუკეთესო/საშუალო შემთხვევის დამტკიცება: T(n) = 2T(n/2) + O(n) — ზუსტად იგივე რეკურენტული დამოკიდებულება, რაც Merge Sort-ს ჰქონდა ლექცია 4-ში → O(n log n). განსხვავება მხოლოდ იმაშია, რომ აქ O(n) სამუშაო partition-ზე იხარჯება, merge-ის ნაცვლად.

რეალურად გაშვებული Lomuto partition-ის შედარებების რაოდენობაა — არა თეორიული შეფასება. სცადეთ სხვადასხვა n.

🎲

რატომ შველის შემთხვევითი Pivot? ზემოთ ნახეთ, რომ დალაგებულ მასივზე ბოლო-ელემენტიანი Pivot-ი კატასტროფულია. გამოსავალი მარტივია: partition()-ის დაწყებამდე ვირჩევთ შემთხვევით ინდექსს [low, high]-დან და ვცვლით მას ბოლო ელემენტთან — შემდეგ ჩვეულებრივი Lomuto Partition გრძელდება. ეს არ იცვლის უარეს-შემთხვევით სირთულეს (თეორიულად კვლავ არსებობს O(n²) შანსი), მაგრამ პრაქტიკულად ხდის მას განსაკუთრებით ნაკლებსავარაუდოდ ნებისმიერ კონკრეტულ შემავალ მონაცემზე.

06 — ალტერნატივა

Hoare-ს სქემა

Hoare-ს (ორიგინალი) სქემა ორ მაჩვენებელს იყენებს — ერთი მარცხნიდან, ერთი მარჯვნიდან — რომლებიც ერთმანეთისკენ მოძრაობენ, სანამ არ იპოვიან „ინვერსიას" (მარცხნივ დიდი, მარჯვნივ პატარა ელემენტი) და მათ ცვლიან ადგილებს.

hoare_partition.py
def hoare_partition(arr: list, low: int, high: int) -> int:
    pivot = arr[low]
    i, j = low - 1, high + 1
    while True:
        i += 1
        while arr[i] < pivot:
            i += 1
        j -= 1
        while arr[j] > pivot:
            j -= 1
        if i >= j:
            return j                # ყურადღება: აბრუნებს j-ს, არა Pivot-ის საბოლოო ინდექსს!
        arr[i], arr[j] = arr[j], arr[i]

def quick_sort_hoare(arr: list, low: int, high: int) -> None:
    if low < high:
        pi = hoare_partition(arr, low, high)
        quick_sort_hoare(arr, low, pi)      # ⚠ pi, არა pi − 1!
        quick_sort_hoare(arr, pi + 1, high)
🔬

დახვეწილი, ხშირად გამოტოვებული დეტალი: Lomuto-ს partition() აბრუნებს Pivot-ის ზუსტ, საბოლოო ინდექსს — ამიტომ რეკურსია იყოფა (low, pi−1) და (pi+1, high)-ად. Hoare-ს სქემა კი არ უზრუნველყოფს, რომ Pivot თავად აღმოჩნდეს ინდექს j-ზე — j უბრალოდ ყოფს მასივს ორ ჯგუფად. ამიტომ რეკურსიაც განსხვავებულია: (low, pi) და (pi+1, high). ამ განსხვავების გამოტოვება ერთ-ერთი ყველაზე გავრცელებული ბაგია, რომელსაც სტუდენტები დებენ, როცა Lomuto-ს რეკურსიის შაბლონს Hoare-ს partition-თან ერთად იყენებენ.

გავზომეთ რეალურად, რამდენ გაცვლას (swap) სჭირდება თითოეული სქემა 200-ელემენტიან შემთხვევით მასივზე, 50 გაშვების საშუალოდ:

სქემასაშუალო swap-ების რაოდენობა (n=200)
Lomuto≈ 923
Hoare≈ 362 (2.5× ნაკლები)

ორივე კოდი ჩვენს მიერ ცალკე გაშვებული და გადამოწმებულია — შედეგი ცხადყოფს, რატომ ითვლება Hoare-ს სქემა უფრო ეფექტურად, თუნდაც ორივეს ერთი და იგივე ასიმპტოტური კლასი ჰქონდეს.

07 — ვის რჩება, ვის — არა

დადებითი და უარყოფითი მხარეები

დადებითიუარყოფითი
Cache-მეგობრულია — მუშაობს იმავე მასივზე, დამატებითი მასივის კოპირების გარეშე (განსხვავებით Merge Sort-ისგან) უარეს შემთხვევაში O(n²) — არასწორი Pivot-ის არჩევისას
საჭიროებს მცირე დამატებით მეხსიერებას — O(log n) call stack-ისთვის მცირე მონაცემებზე Insertion Sort ხშირად სწრაფია — ნაკლები overhead
პრაქტიკაში ხშირად ყველაზე სწრაფია დიდ, შემთხვევით მონაცემებზე არასტაბილურია — თანაბარი ელემენტების თავდაპირველი წესრიგი არ ინარჩუნება
🔍

კავშირი ლექცია 4-თან: გახსოვთ, Merge Sort-ის სტაბილურობა ერთი სიმბოლოს (<= vs <) ცვლილებაზე იყო დამოკიდებული? Quick Sort-ში საერთოდ ვერანაირად ვერ „გამოვასწორებთ" ამას — Pivot-ის გარშემო გადაცვლა ბუნებრივად კარგავს ტოლი ელემენტების ურთიერთწესრიგს, რადგან შედარება ხდება მხოლოდ მნიშვნელობებზე, პოზიციაზე კი არა. ეს დადასტურდა ჩვენს მიერ გაშვებული ტესტითაც: [('3','a'), ('1','b'), ('3','c'), ('2','d'), ('3','e')]-ის Lomuto-თი დალაგების შემდეგ, სამეულების წესრიგი გახდა ['c', 'a', 'e'] — არა თავდაპირველი ['a', 'c', 'e'].

08 — რეალურ სამყაროში

Quick Sort პროდაქშენში

🔧

C-ის qsort()

C სტანდარტული ბიბლიოთეკის qsort() ისტორიულად Quick Sort-ის ვარიაციაზეა დაფუძნებული — სახელწოდებაც კი პირდაპირ ამაზე მიუთითებს.

⚡

Introsort — ჰიბრიდული გამოსავალი

C++-ის std::sort იყენებს Introsort-ს — იწყებს Quick Sort-ით, მაგრამ თუ რეკურსია ძალიან ღრმავდება (უარესი შემთხვევის ნიშანი), გადადის Heap Sort-ზე, გარანტირებული O(n log n)-ისთვის. ეს პირდაპირი პასუხია დღეს ნასწავლ "უარეს შემთხვევაზე".

Quickselect — k-ური სტატისტიკა

ინტერაქტიული სავარჯიშოები

საბაზისო სავარჯიშოები

1. N = 5, arr = [4, 1, 3, 9, 7] და N = 9, arr = [2, 1, 6, 10, 4, 1, 3, 9, 7] — დაწერეთ partition() და quickSort() 
def partition(arr: list, low: int, high: int) -> int:
    pivot = arr[high]
    i = low - 1
    for j in range(low, high):
        if arr[j] <= pivot:
            i += 1
            arr[i], arr[j] = arr[j], arr[i]
    arr[i + 1], arr[high] = arr[high], arr[i + 1]
    return i + 1

def quick_sort(arr: list, low: int, high: int) -> None:
    if low < high:
        pi = partition(arr, low, high)
        quick_sort(arr, low, pi - 1)
        quick_sort(arr, pi + 1, high)

Sort Colors მარტივი

დაალაგეთ მასივი, რომელიც შეიცავს მხოლოდ 0, 1, 2 — ერთი გავლით (LeetCode 75) — სამმხრივი partition-ის (Dutch National Flag) კლასიკური მაგალითი.

def sort_colors(nums: list) -> None:
    low, mid, high = 0, 0, len(nums) - 1
    while mid <= high:
        if nums[mid] == 0:
            nums[low], nums[mid] = nums[mid], nums[low]
            low += 1; mid += 1
        elif nums[mid] == 1:
            mid += 1
        else:
            nums[mid], nums[high] = nums[high], nums[mid]
            high -= 1

Kth Largest Element in an Array საშუალო

იპოვეთ k-ური უდიდესი ელემენტი, სრული დალაგების გარეშე (LeetCode 215) — Quickselect-ის კლასიკური გამოყენება.

def find_kth_largest(nums: list, k: int) -> int:
    nums = nums[:]
    target = len(nums) - k          # k-ური უდიდესი = (n-k)-ური ზრდადობით

    def partition(low, high):
        pivot = nums[high]
        i = low - 1
        for j in range(low, high):
            if nums[j] <= pivot:
                i += 1
                nums[i], nums[j] = nums[j], nums[i]
        nums[i + 1], nums[high] = nums[high], nums[i + 1]
        return i + 1

    lo, hi = 0, len(nums) - 1
    while True:
        pi = partition(lo, hi)
        if pi == target:
            return nums[pi]
        elif pi < target:
            lo = pi + 1
        else:
            hi = pi - 1

განსხვავებით სრული Quick Sort-ისგან, აქ მხოლოდ ერთი მხარეს ვაგრძელებთ რეკურსიას (იმის მიხედვით, სად მდებარეობს target) — არა ორივეს. ეს ამცირებს საშუალო სირთულეს O(n log n)-დან O(n)-მდე.

Top K Frequent Elements რთული

დააბრუნეთ k ყველაზე ხშირად განმეორებადი ელემენტი (LeetCode 347) — Quickselect-ის იდეა, გამოყენებული სიხშირეებზე, hash map-თან კომბინაციაში.

from collections import Counter

def top_k_frequent(nums: list, k: int) -> list:
    count = Counter(nums)
    unique = list(count.keys())

    def partition(low, high):
        pivot = count[unique[high]]
        i = low - 1
        for j in range(low, high):
            if count[unique[j]] <= pivot:
                i += 1
                unique[i], unique[j] = unique[j], unique[i]
        unique[i + 1], unique[high] = unique[high], unique[i + 1]
        return i + 1

    target = len(unique) - k
    lo, hi = 0, len(unique) - 1
    while lo < hi:
        pi = partition(lo, hi)
        if pi == target:
            break
        elif pi < target:
            lo = pi + 1
        else:
            hi = pi - 1
    return unique[len(unique) - k:]

იდეა: ვქმნით (მნიშვნელობა → სიხშირე) სიხშირეთა ცხრილს (O(n)), შემდეგ Quickselect-ს ვატარებთ არა თავად რიცხვებზე, არამედ მათ სიხშირეებზე — ვეძებთ არა კონკრეტულ მნიშვნელობას, არამედ პარტიციის ისეთ წერტილს, სადაც ზუსტად k ყველაზე ხშირი ელემენტი რჩება მარჯვნივ. საშუალო სირთულე: O(n).
