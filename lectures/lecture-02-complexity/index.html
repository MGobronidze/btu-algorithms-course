ალგორითმის სირთულის ანალიზი

როგორ შევაფასოთ ალგორითმის ეფექტურობა კომპიუტერისა და იმპლემენტაციის მიუხედავად — და რატომ არის „რამდენ ხანს გაშვებული იყო" არასწორი შეკითხვა.

01 — გამოწვევა

რატომ არ კმარა დროის გაზომვა?

ერთსა და იმავე ამოცანას ბევრი განსხვავებული ალგორითმული ამოხსნა შეიძლება ჰქონდეს. ბუნებრივი შეკითხვაა: როდის სჯობს ერთი მეორეს? პასუხი — როცა ნაკლებ რესურსს ხარჯავს: დროს ან მეხსიერებას. ერთი გზა ამის შესაფასებლად — უბრალოდ გავზომოთ გაშვების დრო:

timing.py
import time

def c_to_f(c: float) -> float:
    return c * 9 / 5 + 32

start = time.perf_counter()
c_to_f(100_000)
elapsed = time.perf_counter() - start
print(f"დრო: {elapsed:.8f} წამი")
🔍

შესწორება ორიგინალი მასალიდან: საწყისი კოდი იყენებდა time.clock()-ს — ეს ფუნქცია Python 3.3-დან მოძველებულად იყო გამოცხადებული და საბოლოოდ წაშლილია Python 3.8-დან. თანამედროვე სტანდარტული ალტერნატივაა time.perf_counter() (ყველაზე ზუსტი, wall-clock დროისთვის) ან time.process_time() (მხოლოდ CPU-ს დროისთვის, I/O ლოდინის გარეშე).

მაგრამ დროის გაზომვას რამდენიმე ფუნდამენტური პრობლემა აქვს, როცა მიზანი ალგორითმის (და არა კონკრეტული პროგრამის) შეფასებაა:

პრობლემარატომ ერევა შეფასებას
განსხვავებული იმპლემენტაციაიგივე ალგორითმი სხვადასხვანაირად შეიძლება დაიწეროს
განსხვავებული კომპიუტერიპროცესორის სიმძლავრე ცვლის შედეგებს, არა ალგორითმის ხარისხს
განსხვავებული შემავალი მონაცემირამდენიმე გაზომვით შეუძლებელია ზუსტი კავშირის დანახვა ზომასა და დროს შორის

შემდეგი მცდელობა — დროის ნაცვლად ოპერაციების რაოდენობის დათვლა. ეს გამორიცხავს კომპიუტერის სიმძლავრის ფაქტორს, მაგრამ კვლავ რჩება დამოკიდებული კონკრეტულ იმპლემენტაციაზე (რომელი ოპერაცია ჩავთვალოთ „საბაზისოდ"?). საბოლოო გამოსავალი — ორივეს გვერდის ავლა და ყურადღების გადატანა ზრდის რიგზე (growth rate): რამდენად სწრაფად იზრდება საჭირო სამუშაო, როცა შემავალი მონაცემის ზომა იზრდება.

02 — შუალედური ნაბიჯი

ნაბიჯების დათვლა

დავუშვათ, თითოეულ პრიმიტიულ ნაბიჯს (მათემატიკური ოპერაცია, შედარება, მინიჭება, მეხსიერებაში წვდომა) თანაბარი დრო სჭირდება. მაშინ ოპერაციათა რაოდენობა შეგვიძლია განვსაზღვროთ შემავალი ცვლადის ფუნქციად:

fact_iter.py
def fact_iter(n: int) -> int:
    """მოსალოდნელია n >= 0."""
    answer = 1                # 1 ნაბიჯი
    while n > 1:               # მოწმდება n-ჯერ
        answer *= n            # სრულდება (n-1)-ჯერ
        n -= 1                 # სრულდება (n-1)-ჯერ
    return answer              # 1 ნაბიჯი

ჯამში — დაახლოებით 5n − 2 ნაბიჯი. მაგრამ ეს ზუსტი რიცხვი დიდ სურათს არაფერს გვეუბნება: ჩვენ გვაინტერესებს, თუ როგორ იზრდება ეს რიცხვი, n-ის ზრდასთან ერთად — არა ზუსტი მუდმივები.

✂️

ორი გამარტივების წესი: ასიმპტოტური ანალიზისას (1) უგულებელვყოფთ ადიციურ მუდმივებს (5n − 2 → 5n) და (2) უგულებელვყოფთ მულტიპლიკაციურ მუდმივებს (5n → n). შედეგი: fact_iter-ის ასიმპტოტური სირთულეა O(n).

გამოსახულებაგამარტივებული Big-O
n² + 2n + 2O(n²)
n² + 100000n + 3¹⁰⁰⁰O(n²)
log(n) + n + 4O(n)
0.0001·n·log(n) + 300nO(n log n)
2n³⁰ + 3ⁿO(3ⁿ)

ყოველთვის ვინარჩუნებთ მხოლოდ ყველაზე სწრაფად მზარდ წევრს — მას, რომელიც დომინირებს, როცა n ძალიან დიდი ხდება.

03 — შემავალზე დამოკიდებულება

საუკეთესო, საშუალო და უარესი შემთხვევა

ერთი და იმავე ალგორითმის სირთულე შეიძლება განსხვავდებოდეს იმის მიხედვით, თუ რა მონაცემი მოვა შესატანად:

search_for_elmt.py
def search_for_elmt(L: list, e) -> bool:
    for i in L:
        if i == e:
            return True
    return False
შემთხვევარას ნიშნავს
საუკეთესოსაძიებელი ელემენტი — სიის პირველივე წევრი. მინიმალური დრო, სიის სიგრძის მიუხედავად.
საშუალოელემენტი საშუალოდ სიის შუაში გვხვდება.
უარესიელემენტი საერთოდ არ არის სიაში — მთლიანი სიის შემოწმებაა საჭირო.
🎯

რატომ ვამახვილებთ ყურადღებას უარეს შემთხვევაზე: ზრდის რიგის დახასიათებისას, კურსის განმავლობაში თითქმის ყოველთვის worst case-ზე ვისაუბრებთ — ეს არის გარანტია: „ალგორითმი არასდროს იმუშავებს ამაზე ნელა", რაც კრიტიკულია production სისტემებისთვის, სადაც გაუთვალისწინებელი, „ცუდი" შემავალი მონაცემი ნებისმიერ დროს შეიძლება მოვიდეს.

04 — ფორმალური აღნიშვნა

O-დიდი

O-დიდი — ასიმპტოტური აღნიშვნაა, რომელიც აღწერს ფუნქციის ყოფაქცევას ზღვარში, როცა არგუმენტი (შემავალი მონაცემის ზომა) მიისწრაფვის უსასრულობისკენ. ის გვაძლევს მოხერხებულ კლასიფიკაციას ფუნქციებისთვის მათი ზრდის რიგის მიხედვით — ზუსტი მნიშვნელობის ნაცვლად.

O-დიდის განსაზღვრებისას სამი პრინციპი გვხელმძღვანელობს:

  1. გვაინტერესებს, რამდენად სწრაფად იზრდება საჭირო დრო, როცა შემავალი მონაცემის ზომა იზრდება — არა ზუსტი მნიშვნელობა კონკრეტულ n-ზე.
  2. ვაკვირდებით უარეს შემთხვევას — ზრდის ზედა საზღვარს (upper bound), რაც შეიძლება მჭიდროდ.
  3. ვინარჩუნებთ მხოლოდ ყველაზე სწრაფად მზარდ ტერმს, უგულებელვყოფთ მუდმივებს — მათემატიკურად: O(f(n)), თუ არსებობს დადებითი მუდმივები c და n₀, ისეთი, რომ ნებისმიერი n ≥ n₀-სთვის ალგორითმის ნაბიჯების რაოდენობა ≤ c · f(n).
05 — ტაქსონომია

კომპლექსურობის კლასები

კომპლექსურობის კლასები გვეხმარება განვსაზღვროთ, რამდენი დრო (ან მეხსიერება) დასჭირდება ალგორითმს, როცა მონაცემთა რაოდენობა იზრდება — უმცირესიდან უდიდესამდე:

კლასიდახასიათებამაგალითიშეფასება
O(1)მუდმივი დრო — არ არის დამოკიდებული მონაცემთა რაოდენობაზე.მასივში ელემენტზე პირდაპირი წვდომაძალიან სწრაფი
O(log n)ლოგარითმული — ყოველ ნაბიჯზე მონაცემი ნახევრდება.ორობითი ძებნა დალაგებულ სიაშისწრაფი
O(n)წრფივი — ყოველი ელემენტის ერთხელ გავლა.ძებნა დაულაგებელ სიაშინორმალური
O(n log n)ლოგ-ხაზოვანი — n-ჯერადი ოპერაცია, თითოეული ლოგარითმული ხარჯით.Merge Sort, Quick Sortდასაშვები
O(n²)კვადრატული (პოლინომური) — ჩადგმული წრფივი ციკლი.ორი სიის თანაკვეთის ნაივური ძებნანელი
O(2ⁿ)ექსპონენციალური — იზრდება კატასტროფულად სწრაფად.ფიბონაჩის ნაივური რეკურსიაპრაქტიკულად გამოუსადეგარი

ზოლების სიგრძე ლოგარითმულ შკალაზეა (თორემ O(2ⁿ) დანარჩენებს უხილავს გახდიდა) — მარჯვნივ მოცემული რიცხვი კი ზუსტი ოპერაციების რაოდენობაა მოცემულ n-ზე. გადაათრიეთ სლაიდერი — შეამჩნევთ, რამდენად სწრაფად „გაექცევა" ექსპონენციალური კლასი დანარჩენებს.

06 — კომბინირება

პროგრამებისა და მათი სირთულეების გაანალიზება

როცა ალგორითმი რამდენიმე ნაწილისგან შედგება, ორი მარტივი წესი გვეხმარება საერთო სირთულის დათვლაში:

შეკრების წესი — თანმიმდევრული ბლოკები

O(f(n)) + O(g(n)) = O(f(n) + g(n)) — ვინარჩუნებთ დომინანტს.

def combo(n: int) -> None:
    for i in range(n):        # O(n)
        print('a')
    for j in range(n * n):    # O(n²)
        print('b')
# ჯამის წესი: O(n) + O(n²) = O(n + n²) = O(n²)

ნამრავლის წესი — ჩადგმული ციკლები

O(f(n)) × O(g(n)) = O(f(n) · g(n))

def nested(n: int) -> int:
    x = 0
    for i in range(n):        # გარე ციკლი — n-ჯერ
        for j in range(n):    # შიდა ციკლი — n-ჯერ, ყოველ გარე იტერაციაზე
            x += 1
    return x
# ნამრავლის წესი: O(n) × O(n) = O(n²)
💡

ზოგადი წესი: თუ ციკლები თანმიმდევრულია (ერთმანეთის მიყოლებით) — ვკრებთ. თუ ციკლი ჩადგმულია მეორეში — ვამრავლებთ. სამშრიანი ჩადგმული ციკლი (n-ზე დამოკიდებული სამივე) — O(n³), და ასე შემდეგ.

07 — მაგალითები კლასების მიხედვით

რეალური მაგალითები, დახარისხებული

O(1) — მასივში ელემენტზე წვდომა

            return True
        if x > e:      # აღარაა აზრი გაგრძელებას
            return False
    return False

ორივე ვერსია O(n) უარეს შემთხვევაში. დალაგებული ვერსია საშუალოდ სწრაფია (ადრე წყდება), მაგრამ ეს ასიმპტოტურ კლასს არ ცვლის — მხოლოდ პრაქტიკულ, კონსტანტურ გაუმჯობესებას იძლევა. (მომდევნო ლექციებში ვნახავთ, როგორ გვაძლევს დალაგებული მონაცემი გაცილებით ძლიერ ინსტრუმენტს — ორობით ძებნას, O(log n)-ს.)

O(n²) — ჩადგმული ციკლები ორ სიაზე

განვსაზღვროთ, არის თუ არა ერთი სია მეორის ქვესიმრავლე:

def is_subset(L1: list, L2: list) -> bool:
    for e1 in L1:
        matched = False
        for e2 in L2:
            if e1 == e2:
                matched = True
                break
        if not matched:
            return False
    return True
# O(len(L1) * len(L2))
🔍

ინდუსტრიული გაუმჯობესება: ჩადგმული ციკლი მუშაობს, მაგრამ Python-ის set სტრუქტურა (რომელსაც heap-ისა და hash table-ების შემდეგ უფრო დეტალურად შევისწავლით) საშუალო შემთხვევაში O(1)-ში ამოწმებს წევრობას. ამის წყალობით, იგივე ამოცანა O(n + m)-ში — ანუ წრფივ დროში — წყდება:

def is_subset_fast(L1: list, L2: list) -> bool:
    return set(L1) <= set(L2)

იგივე ეხება ორი სიის თანაკვეთის პოვნასაც. საწყისი ვერსია მუშაობს ორ ნაბიჯად — ჯერ პოულობს საერთო ელემენტებს ჩადგმული ციკლით, შემდეგ ცალკე ციკლში იშორებს დუბლიკატებს:

def intersect(L1: list, L2: list) -> list:
    tmp = []
    for e1 in L1:
        for e2 in L2:
            if e1 == e2:
                tmp.append(e1)
    res = []
    for e in tmp:
        if not (e in res):   # ეს შემოწმებაც თავად O(len(res))-ია!
            res.append(e)
    return res
⚠️

ფარული სირთულე: if not (e in res) თავადაც წრფივი ძებნაა სიაში — ანუ დუბლიკატების მოცილების ციკლიც შეიძლება O(len(tmp)²)-მდე გაიზარდოს უარეს შემთხვევაში, თუმცა ეს არ ცვლის საბოლოო O(n²) კლასს, რადგან ორივე ნაწილი ერთი და იმავე რიგისაა. მაგრამ სუფთა, თანამედროვე ამოხსნა სულაც გვერდს უვლის ამ პრობლემას:

def intersect_fast(L1: list, L2: list) -> list:
    return list(set(L1) & set(L2))   # O(n + m)
08 — O(2ⁿ) vs O(n)

ფიბონაჩი: რამდენად შეიძლება „ავფეთქდეს" სირთულე

ფიბონაჩის ნაივური რეკურსია — ზუსტად ის მაგალითია, სადაც ერთი მარტივი შეცვლა სირთულეს ექსპონენციალურიდან წრფივამდე ამცირებს.

ნაივური რეკურსია — O(2ⁿ)
def fibonacci(n: int) -> int:
    if n == 0:
        return 0
    elif n == 1:
        return 1
    else:
        return fibonacci(n - 1) + fibonacci(n - 2)
დინამიკური პროგრამირება — O(n)
def fibonacci_dp(n: int, memo: dict | None = None) -> int:
    if memo is None:
        memo = {}
    if n in memo:
        return memo[n]
    if n == 0:
        return 0
    if n == 1:
        return 1
    memo[n] = fibonacci_dp(n - 1, memo) + fibonacci_dp(n - 2, memo)
    return memo[n]
🔍

მნიშვნელოვანი შესწორება — მოდიფიცირებადი ნაგულისხმევი არგუმენტი: ორიგინალი მასალის კოდი წერდა def fibonacci_dp(n, memo={}):. ეს Python-ის ერთ-ერთი ყველაზე ცნობილი „ხაფანგია": ნაგულისხმევი მნიშვნელობა ({}) იქმნება მხოლოდ ერთხელ — ფუნქციის განსაზღვრის დროს, არა ყოველ გამოძახებაზე — და ყველა შემდგომი გამოძახება იმავე dictionary-ს იზიარებს. ამან შეიძლება წარმოშვას ძნელად აღმოსაჩენი ბაგები, თუ ფუნქცია სხვადასხვა, დაუკავშირებელი გამოძახებებისთვის გამოიყენება. სწორი პატერნია: memo: dict | None = None, შემდეგ ფუნქციის სხეულში if memo is None: memo = {}.

ვერსიადროითი სირთულე
ნაივური რეკურსიაO(2ⁿ)
memoization (fibonacci_dp)O(n)
🏭

Tech Industry Insight: უფრო იდიომატური Python-ის გზა იგივის მისაღწევად — functools.lru_cache დეკორატორი, რომელიც ზუსტად ამ მემოიზაციის პატერნს გვთავაზობს ჩაშენებულად, მოდიფიცირებადი default-ის ხაფანგის გარეშე:

from functools import lru_cache

@lru_cache(maxsize=None)
def fibonacci(n: int) -> int:
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)
09 — რატომ აქცევს ამას ყურადღებას ინდუსტრია

Big-O რეალურ სამყაროში

🎤

ტექნიკური გასაუბრებები

Big-O ანალიზი Google-ის, Amazon-ისა და Meta-ის ინჟინრების გასაუბრებების სტანდარტული ნაწილია — არა კონკურსისთვის, არამედ იმიტომ, რომ არასწორად შერჩეული ალგორითმი production-ში მილიონობით მომხმარებელზე აისახება.

🗄️

მონაცემთა სტრუქტურის არჩევანი

Python-ის list-ში წევრობის შემოწმება — O(n), მაგრამ set-ში ან dict-ში — საშუალოდ O(1). სწორედ ეს განსხვავება წყვეტს, დაიტვირთება თუ არა ვებ-გვერდი წამში, თუ წუთებში, როცა მონაცემი მილიონობით ჩანაწერს აღწევს.

📈

მასშტაბირებადობა (Scalability)

O(n²) ალგორითმი, რომელიც 1,000 ჩანაწერზე მილიწამებში მუშაობს, 1,000,000 ჩანაწერზე შეიძლება საათობით გაგრძელდეს — 1000² = 1,000,000-ჯერადი ზრდა. ეს ხშირად რეალურ production incident-ებში აღმოჩენილი პრობლემაა.

💰

ინფრასტრუქტურის ხარჯი

Cloud-ში (AWS, GCP) გამოთვლითი დრო პირდაპირ ფულად ხარჯად გარდაიქმნება. O(n log n) ალგორითმზე გადასვლა O(n²)-დან რეალურად ამცირებს კომპანიის ყოველთვიურ ხარჯებსაც.

10 — პრაქტიკა

ინტერაქტიული სავარჯიშოები

შეაფასეთ თითოეული ამოცანის სირთულე, სანამ ამოხსნას გახსნით.

საბაზისო სავარჯიშოები

1. A = [5,3,8,6,2,7,4] — შეამოწმეთ, გვხვდება თუ არა რიცხვი x სიაში 
def search_in_list(A: list, x) -> bool:
    for element in A:
        if element == x:
            return True
    return False

სირთულე: O(n). უარეს შემთხვევაში (x სიაში არ არის, ან ბოლოშია) მთელი სიის გავლაა საჭირო. Pythonic ალტერნატივა იგივე კლასით: x in A.

2. s = "abc123def45" — შეკარით სტრიქონში შემავალი ყველა ციფრი 
def sum_of_digits(s: str) -> int:
    total = 0
    for char in s:
        if char.isdigit():
            total += int(char)
    return total

სირთულე: O(len(s)). თითოეული სიმბოლო ერთხელ მოწმდება — წრფივი დრო.

3. იპოვეთ სიის უდიდესი და უმცირესი ელემენტები 
def find_min_max(A: list) -> tuple:
    if not A:
        raise ValueError("სია ცარიელია")
    min_elem = max_elem = A[0]
    for elem in A:
        if elem < min_elem:
            min_elem = elem
        if elem > max_elem:
            max_elem = elem
    return min_elem, max_elem

სირთულე: O(n). ორიგინალ ვერსიას აკლდა ცარიელი სიის შემოწმება — A[0] ცარიელ სიაზე IndexError-ს გამოიწვევდა. ერთი გავლით ვამოწმებთ ორივე პირობას ერთდროულად, ამიტომ არა O(2n), არამედ ზუსტად O(n) რჩება.

4. ორი სია — დააბრუნეთ ყველა შესაძლო წყვილი ელემენტებისა 
def find_combinations(A: list, B: list) -> list:
    combinations = []
    for a in A:
        for b in B:
            combinations.append((a, b))
    return combinations

სირთულე: O(len(A) · len(B)). ჩადგმული ციკლი — ნამრავლის წესი. სტანდარტული ბიბლიოთეკა ამას გვთავაზობს მზა სახით: list(itertools.product(A, B)).

LeetCode-ტიპის ამოცანები

კლასიკური „ნაივური vs ოპტიმალური" წყვილები — ზუსტად ის აზროვნება, რასაც გასაუბრებებზე ამოწმებენ.

Contains Duplicate მარტივი

განსაზღვრეთ, შეიცავს თუ არა მასივი დუბლირებულ მნიშვნელობას (LeetCode 217).

ნაივური — O(n²)
def contains_duplicate(nums):
    n = len(nums)
    for i in range(n):
        for j in range(i+1, n):
            if nums[i] == nums[j]:
                return True
    return False
set-ით — O(n)
def contains_duplicate(nums):
    return len(set(nums)) != len(nums)

თუ ყველა ელემენტი უნიკალურია, set(nums)-ის სიგრძე იგივე დარჩება — თუ დუბლიკატია, set „შეჭამს" ზედმეტ ასლებს და სიგრძე შემცირდება.

Two Sum საშუალო

იპოვეთ ორი ინდექსი, რომელთა მნიშვნელობების ჯამი უდრის target-ს (LeetCode 1) — ალბათ ყველაზე ცნობილი Big-O გაკვეთილი ინდუსტრიაში.

def two_sum(nums: list, target: int) -> list:
    seen = {}                       # მნიშვნელობა → ინდექსი
    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:      # O(1) საშუალოდ
            return [seen[complement], i]
        seen[num] = i
    return []

ნაივური ამოხსნა ყოველ წყვილს ჩადგმული ციკლით ამოწმებს — O(n²). ერთი dict-ის დამატებით ამოცანა O(n)-მდე დაიყვანება: ყოველ ელემენტზე ვამოწმებთ, უკვე გვინახავს თუ არა „დაკლებული" მნიშვნელობა — კლასიკური space-for-time trade-off (მეტი მეხსიერება ნაკლები დროის სანაცვლოდ).

Maximum Subarray (Kadane's Algorithm) რთული

იპოვეთ მასივის უწყვეტი ქვემასივი მაქსიმალური ჯამით (LeetCode 53).

def max_subarray(nums: list) -> int:
    best = current = nums[0]
    for x in nums[1:]:
        current = max(x, current + x)
        best = max(best, current)
    return best

ნაივური ამოხსნა ყველა შესაძლო ქვემასივს ცალ-ცალკე ჯამავს — O(n²) ან უარესიც. კადანეს იდეა: თითოეულ პოზიციაზე ვირჩევთ — გავაგრძელოთ მიმდინარე ქვემასივი, თუ დავიწყოთ ახალი? ეს ერთი გავლა ალგორითმს O(n)-მდე ამცირებს — კლასიკური მაგალითი იმისა, თუ როგორ გვშველის სწორი „ლოკალური" დაკვირვება გლობალურად ოპტიმალურ ამოხსნაზე გადასვლისას (დინამიკური პროგრამირების საწყისები, რასაც შემდეგ კვირებში კიდევ შევეხებით).
