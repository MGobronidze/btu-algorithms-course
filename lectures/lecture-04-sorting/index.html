01 — რატომ დალაგება

ორობითი ძებნიდან დალაგებამდე

ლექცია 3-ში ვნახეთ, რომ ორობითი ძებნა — O(log n) — მუშაობს მხოლოდ დალაგებულ სტრუქტურაზე. მაგრამ თუ მონაცემი დაულაგებელი მოვიდა? სანამ ორობითი ძებნის სიჩქარეს ვისარგებლებთ, პირველ ჯერზე ის უნდა დავალაგოთ — და დღეს ვსწავლობთ ორ ურთიერთსაწინააღმდეგო ფილოსოფიას ამისთვის.

02 — გვერდითი შენიშვნა

Bisection Search — ორობითი ძებნა უწყვეტ სამყაროში

ორობითი ძებნის იდეა მასივებს არ ეზღუდება. Bisection search იმავე „განახევრების" პრინციპს იყენებს უწყვეტი ფუნქციის ფესვის საპოვნელად — ეფუძნება შუალედური მნიშვნელობის თეორემას (Intermediate Value Theorem): თუ უწყვეტი ფუნქცია f(x) ნიშანს იცვლის [a, b] შუალედზე (ანუ f(a) · f(b) < 0), მაშინ მას აქვს ფესვი ამ შუალედში.

bisection_search.py
def bisection_search(f, a: float, b: float, tol: float = 1e-6) -> float:
    if f(a) * f(b) >= 0:
        raise ValueError("f(a)-სა და f(b)-ს საწინააღმდეგო ნიშანი უნდა ჰქონდეთ.")
    while (b - a) / 2 > tol:
        m = (a + b) / 2
        if f(m) == 0:
            return m                # ზუსტად ვიპოვეთ ფესვი
        elif f(a) * f(m) < 0:
            b = m                   # ფესვი მარცხენა ნახევარშია
        else:
            a = m                   # ფესვი მარჯვენა ნახევარშია
    return (a + b) / 2

# √2-ის მოძებნა: f(x) = x² − 2-ის ფესვი
print(bisection_search(lambda x: x**2 - 2, 0, 2))   # ≈ 1.4142135...
🔎

განსხვავება მასივის ორობითი ძებნისგან: აქ n აღარ არის „ელემენტების რაოდენობა" — არეალი უწყვეტია. სირთულეს განსაზღვრავს არა შესატანი მონაცემის ზომა, არამედ სასურველი სიზუსტე: საჭირო ნაბიჯების რაოდენობაა log₂((b−a)/tol). მაინც იგივე ლოგარითმული ბუნებაა — ყოველ ნაბიჯზე განუსაზღვრელობის არეალი ნახევრდება.

03 — პირველი დალაგების ალგორითმი

Insertion Sort

იდეა ბუნებრივია — ზუსტად ისე ალაგებთ სათამაშო ბანქოს ხელში: იღებთ შემდეგ ბარათს და სვამთ უკვე დალაგებულ ნაწილში სწორ ადგილას.

  1. ვიწყებთ მეორე ელემენტიდან (პირველი, ცალკე აღებული, ავტომატურად „დალაგებულია").
  2. მიმდინარე ელემენტს (key) ვადარებთ მის მარცხნივ მდგომ, უკვე დალაგებულ ნაწილს.
  3. ყველა ელემენტს, რომელიც key-ზე დიდია, ერთი პოზიციით მარჯვნივ ვწევთ.
  4. ვსვამთ key-ს გამოთავისუფლებულ ადგილას. ვიმეორებთ მთელი მასივისთვის.
insertion_sort.py
def insertion_sort(arr: list) -> list:
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1
        # ვწევთ დალაგებული ნაწილის ელემენტებს მარჯვნივ,
        # სანამ არ ვიპოვით key-ს სწორ ადგილას
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key
    return arr

სირთულის ანალიზი

შემთხვევარა ხდებასირთულე
საუკეთესომასივი უკვე დალაგებულია — თითოეულ ელემენტს მხოლოდ ერთხელ ვადარებთ წინამორბედს, გადანაცვლება არ ხდებაO(n)
უარესიმასივი კლებადობითაა დალაგებული — თითოეული ელემენტი მთელ დალაგებულ ნაწილს გაივლისO(n²)
∑

უარესი შემთხვევის დამტკიცება: პირველ იტერაციაზე მაქსიმუმ 1 შედარებაა საჭირო, მეორეზე — მაქსიმუმ 2, ..., ბოლოზე — მაქსიმუმ n−1. ჯამი: 1 + 2 + ⋯ + (n−1) = n(n−1)/2, რაც არის O(n²).

მეხსიერება: ალგორითმი მუშაობს ადგილზე (in-place) — დამატებითი მასივი არ სჭირდება, ამიტომ სივრცითი სირთულეა O(1).

04 — სცადეთ თავად

Insertion Sort ნაბიჯ-ნაბიჯ

ოქროსფერი — მიმდინარე key. მწვანე — უკვე დალაგებული ნაწილი. დააჭირეთ „შემდეგი ნაბიჯი" და თვალი ადევნეთ, როგორ „იძვრის" თითოეული ელემენტი თავის ადგილას.

✅

უპირატესობები: მარტივი და ადვილად წასაკითხი; სტაბილურია (თანაბარი ელემენტების ურთიერთწესრიგი არ ირღვევა); ძალიან ეფექტურია მცირე ან „თითქმის დალაგებულ" მონაცემზე — ე.წ. adaptive თვისება; ადგილზე მუშაობს, დამატებითი მეხსიერების გარეშე.
ნაკლი: არაეფექტურია დიდი, შემთხვევითად დალაგებული მონაცემისთვის — O(n²) სწრაფად ხდება პრობლემა.

05 — დაყავი და იბატონე

Merge Sort

Merge Sort სრულიად განსხვავებული ფილოსოფიით მუშაობს — divide and conquer: მასივს ვყოფთ ორ ნახევრად, თითოეულს რეკურსიულად ვალაგებთ, შემდეგ ორ დალაგებულ ნახევარს ვაერთიანებთ (merge) ერთ დალაგებულ მასივში.

  1. საბაზისო შემთხვევა: თუ სიის სიგრძეა 0 ან 1 — უკვე დალაგებულია.
  2. გაყოფა: სიას ვყოფთ ორ თანაბარ ნახევრად და ორივეს რეკურსიულად ვალაგებთ.
  3. გაერთიანება: ვადარებთ ორივე დალაგებული ნახევრის „წამყვან" ელემენტებს — პატარას გადმოვაქვთ შედეგში; როცა ერთი ნახევარი ცარიელდება, მეორის დარჩენილს პირდაპირ ვაკოპირებთ.
merge_sort.py
def merge_sort(arr: list) -> list:
    if len(arr) <= 1:
        return arr

    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])

    merged = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:      # <= (და არა <) — ინარჩუნებს სტაბილურობას
            merged.append(left[i]); i += 1
        else:
            merged.append(right[j]); j += 1
    merged.extend(left[i:])          # დარჩენილი ელემენტების პირდაპირ დამატება
    merged.extend(right[j:])
    return merged
🔍

დახვეწილი, მაგრამ მნიშვნელოვანი შესწორება: ორიგინალი მასალის კოდი წერდა if left_half[i] < right_half[j] — მკაცრი <. ეს ერთი სიმბოლო ამტვრევს სტაბილურობას: როცა ორივე ნახევარში ტოლი ელემენტებია, < ირჩევს მარჯვენა ნახევრის ელემენტს პირველად — რაც ცვლის თანაბარი ელემენტების საწყის ურთიერთწესრიგს. Merge Sort-ი ცნობილია, როგორც „ბუნებრივად სტაბილური" ალგორითმი — მაგრამ ეს სტაბილურობა მხოლოდ მაშინ ვრცელდება, თუ merge-ის შედარებაში ტოლობისას მარცხენა ნახევარს ვანიჭებთ უპირატესობას (<=). შემოწმებული იქნა ორივე ვერსია — ტესტმა ზუსტად დაადასტურა ეს განსხვავება.

💡

რატომ არის სტაბილურობა მნიშვნელოვანი? წარმოიდგინეთ ცხრილი თანამშრომლების შესახებ, უკვე დალაგებული სახელის მიხედვით ანბანურად. ახლა გინდათ იგივე ცხრილის დალაგება განყოფილების მიხედვით. სტაბილური ალგორითმით, ერთი და იმავე განყოფილების თანამშრომლები კვლავ ანბანურად დარჩება — არასტაბილურით კი ეს წესრიგი დაიკარგება, თითქმის შემთხვევით.

სირთულის ანალიზი

რეკურენტული დამოკიდებულება: T(n) = 2·T(n/2) + O(n)

  • გაყოფა: მასივი ნახევრდება, სანამ არ მივიღებთ ერთელემენტიან ქვემასივებს — log n დონე.
  • გაერთიანება: თითოეულ დონეზე, ყველა merge ოპერაციის ჯამური სამუშაო არის O(n) (ყოველი ელემენტი ერთხელ „გადაინაცვლებს" შედეგში).
მახასიათებელიმნიშვნელობა
დროითი სირთულე (ყველა შემთხვევაში)O(n log n)
სივრცითი სირთულეO(n)

log n დონე × O(n) სამუშაო დონეზე = O(n log n). ეს გარანტირებულია ყველა შემთხვევაში — საუკეთესო, საშუალო თუ უარესი — Insertion Sort-ისგან განსხვავებით, სადაც შემავალმა მონაცემმა შეიძლება მკვეთრად შეცვალოს სირთულე.

⚠️

დამატებითი მეხსიერების წყარო: ზემოთ მოცემული ვერსია ყოველ რეკურსიულ გამოძახებაზე ქმნის ახალ სიებს (arr[:mid], arr[mid:] — slicing Python-ში ყოველთვის ასლს აკეთებს). ესაა O(n) დამხმარე მეხსიერების წყარო — რის გამოც Merge Sort არ ითვლება in-place ალგორითმად, Insertion Sort-ისგან განსხვავებით.

06 — სცადეთ თავად

Merge Sort ნაბიჯ-ნაბიჯ

დააჭირეთ „შემდეგი ნაბიჯი" — ნახავთ ყოველ merge ოპერაციას ცალ-ცალკე, იმ თანმიმდევრობით, როგორც რეკურსია რეალურად ასრულებს მათ (ქვემოდან ზემოთ — ჯერ პატარა ნაწილები, შემდეგ დიდი).

მწვანე ზოლები უკვე თავისი საბოლოო, დალაგებული პოზიციისკენ მოძრაობს ამ merge-ის ფარგლებში; ნაცრისფერი — ჯერ არ შეხებია ამ ეტაპს.

Python-ის ჩაშენებული sorted() და list.sort() იყენებენ Timsort-ს — ჰიბრიდულ ალგორითმს, რომელიც ზუსტად დღეს ნასწავლი ორივე იდეას აერთიანებს: პატარა ქვემონაკვეთებს Insertion Sort-ით ალაგებს (სადაც ის ყველაზე ეფექტურია), შემდეგ მათ Merge Sort-ის პრინციპით აერთიანებს. Java-ს Arrays.sort() ობიექტებისთვის იგივეს აკეთებს.

💾

გარე დალაგება (External Sorting)

როცა მონაცემი დისკზეა და RAM-ში არ ეტევა, Merge Sort-ის პრინციპი (მცირე ნაწილების დალაგება და თანდათანობითი გაერთიანება) გამოიყენება — ბაზების სისტემებში დიდი ცხრილების დასალაგებლად.

🔗

Merge Sort და ბმული სიები

ბმულ სიაზე (რომელსაც მალე შევისწავლით) Merge Sort განსაკუთრებით ბუნებრივია — O(1)-ში შესაძლებელია სიის შუაზე გაყოფა და ელემენტების „მიბმა" ახალი მიმდევრობით, დამატებითი მასივის გარეშეც.

სტაბილურობა real-world მონაცემებში

ცხრილების მრავალსვეტიანი დალაგება (მაგ. Excel-ში ჯერ განყოფილებით, მერე სახელით) სწორედ სტაბილურ დალაგებას ეყრდნობა — ამიტომაა, რომ ინდუსტრიაში სტაბილურობის დარღვევა (როგორც დღეს ვნახეთ < vs <=-ში) სერიოზულ ბაგებამდე მიდის.

09 — პრაქტიკა

ინტერაქტიული სავარჯიშოები

საბაზისო სავარჯიშოები

1. n = 5, arr = [8, 1, 5, 3, 10] — დაალაგეთ Insertion Sort-ით ორი ფუნქციით: insert() და insertionSort() 
def insert(arr: list, n: int, i: int) -> None:
    """ჩასვამს arr[i]-ს დალაგებულ arr[0..i-1]-ში სწორ ადგილას."""
    key = arr[i]
    j = i - 1
    while j >= 0 and arr[j] > key:
        arr[j + 1] = arr[j]
        j -= 1
    arr[j + 1] = key

def insertion_sort(arr: list, n: int) -> None:
    for i in range(1, n):
        insert(arr, n, i)

სირთულე: უარესი O(n²), საუკეთესო O(n) — იგივე ანალიზი, რაც ზემოთ.

2. დაწერეთ ორი ფუნქცია: merge(arr, l, m, r) და mergeSort(arr, l, r) 
def merge(arr: list, l: int, m: int, r: int) -> None:
    left = arr[l:m + 1]
    right = arr[m + 1:r + 1]
    i = j = 0
    k = l
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            arr[k] = left[i]; i += 1
        else:
            arr[k] = right[j]; j += 1
        k += 1
    while i < len(left):
        arr[k] = left[i]; i += 1; k += 1
    while j < len(right):
        arr[k] = right[j]; j += 1; k += 1

def merge_sort(arr: list, l: int, r: int) -> None:
    if l < r:
        m = (l + r) // 2
        merge_sort(arr, l, m)
        merge_sort(arr, m + 1, r)
        merge(arr, l, m, r)

ეს ვერსია ინდექსებით მუშაობს (l, m, r) ახალი სიების დაბრუნების ნაცვლად — CLRS-ის სახელმძღვანელოში მიღებული კლასიკური ფორმატი. სირთულე: O(n log n) დროში, O(n) სივრცეში.

Merge Sorted Array მარტივი

ორი დალაგებული მასივი გაერთიანდეს ერთში, ადგილზე (LeetCode 88) — merge()-ის იდეის პირდაპირი გამოყენება, უკნიდან წინ.

def merge(nums1: list, m: int, nums2: list, n: int) -> None:
    i, j, k = m - 1, n - 1, m + n - 1
    while j >= 0:
        if i >= 0 and nums1[i] > nums2[j]:
            nums1[k] = nums1[i]; i -= 1
        else:
            nums1[k] = nums2[j]; j -= 1
        k -= 1

ვავსებთ nums1-ს ბოლოდან, რომ არ დაგვჭირდეს ჯერ არშედარებული ელემენტების გადაწერა — კლასიკური „ორი მაჩვენებელი ბოლოდან" ხრიკი.

Sort an Array საშუალო

დაწერეთ სრული დალაგების ალგორითმი ნულიდან (LeetCode 912) — ზუსტად დღეს ნასწავლი Merge Sort.

def sort_array(nums: list) -> list:
    if len(nums) <= 1:
        return nums
    mid = len(nums) // 2
    left = sort_array(nums[:mid])
    right = sort_array(nums[mid:])
    merged, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i]); i += 1
        else:
            merged.append(right[j]); j += 1
    return merged + left[i:] + right[j:]
Count of Smaller Numbers After Self რთული

თითოეული ელემენტისთვის დაითვალეთ, რამდენი მისგან მარჯვნივ მდგომი ელემენტია მასზე პატარა (LeetCode 315) — Merge Sort-ის გაცილებით ღრმა გამოყენება, ვიდრე უბრალო დალაგება.

def count_smaller(nums: list) -> list:
    n = len(nums)
    counts = [0] * n
    indices = list(range(n))       # ვალაგებთ ინდექსებს, არა თავად მნიშვნელობებს

    def sort(lo: int, hi: int) -> None:
        if hi - lo <= 1:
            return
        mid = (lo + hi) // 2
        sort(lo, mid)
        sort(mid, hi)
        merged, i, j = [], lo, mid
        while i < mid and j < hi:
            if nums[indices[i]] <= nums[indices[j]]:
                counts[indices[i]] += j - mid   # j-mid ელემენტი მარჯვნიდან უკვე "გავიდა" წინ
                merged.append(indices[i]); i += 1
            else:
                merged.append(indices[j]); j += 1
        while i < mid:
            counts[indices[i]] += j - mid
            merged.append(indices[i]); i += 1
        while j < hi:
            merged.append(indices[j]); j += 1
        indices[lo:hi] = merged

    sort(0, n)
    return counts

იდეა: merge-ის დროს, როცა მარჯვენა ნახევრიდან ელემენტი მარცხენაზე ადრე მოხვდება შედეგში, ეს ნიშნავს, რომ ის ყველა დარჩენილ მარცხენა ელემენტზე პატარაა — და ეს ინფორმაცია „უფასოდ" გვეძლევა, ვინაიდან merge უკვე ასრულებს ამ შედარებებს. სირთულე მცირდება O(n²)-დან (ყველა წყვილის პირდაპირი შედარება) O(n log n)-მდე — ზუსტად merge sort-ის ჩარჩოს წყალობით.
